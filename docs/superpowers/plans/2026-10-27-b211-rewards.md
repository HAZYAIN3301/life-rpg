# B2.11 — Награды на данных аккаунта

> Inline execution; подагенты запрещены владельцем. Продолжение принятого B2.5,
> без нового дизайн-gate: владелец прямо поручил подключить существующий раздел.

**Goal:** Полный перенос Наград, прежде всего своего магазина за золото, без demo wallet.
**Architecture:** B2.5 RewardsWorkspace → отдельный LiveRewards с async bridge.
Исходные economy confirmation/commit, server chest issuer, RewardLifeV1 и owners
коллекции/арсенала/Логова остаются авторитетами. Только изолированный live entry.
**Tech:** React/TS/esbuild, прежний Store/CAS/WAL. База865ebdb0, origin3eca22b1.

## Ограничения и решения

- B2.5 layout/classes/assets неизменны; не редактировать accepted generated-файлы.
- Нет push/deploy, native/auth/B3/attention/3D и чужих файлов.
- Покупки — исходный showEconomyConfirm и economyCommit: pending, durable receipt,
  одинаковые bytes retry, конфликт/баланс/Free limit и Guide-покупка сохраняются.
- История расходов append-only. Статусы в settings.rewardLifeV1, не в purchases.
- Избранная личная награда: settings.personalRewardTargetV1; не заменяет отдельную
  существующую goldGoalV1 для мебели. Используется на Сегодня.
- Отдых-квест: metadata rewardPurchaseId; создаётся через commitmentDataCommit,
  сохраняет реальные сферы и время; lifecycle обновляется тем же WAL при
  переносе/complete/undo. Обычная экономика квестов не меняется.
- Сундук/ваучеры/шансы/история, коллекция/звания/арсенал/реликвии, мебель/накопление,
  достижения/правила/вся история остаются доступны. Ни preview40gold, ни фальшивых ачивок.

## Review focus

Удалённая/переименованная награда сохраняет purchase snapshot; незагруженные slots
не становятся пустым кошельком. Повтор не создаёт покупку/квест дважды. Другой
аккаунт/epoch/stale/недостаточный баланс не применяют эффект. Полный функционал
исходного renderRewards сохраняется без возврата его отвергнутой композиции.
Самопроверка вместо подагента по прямому запрету владельца.
