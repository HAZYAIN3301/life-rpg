# Целостность недельного плана — v324

База c8a747f6/v323. Продолжение карты развития: planning / reliability.
Провайдеры ИИ, платёжные настройки и экономика не менялись. Только синтетические данные.

## Было → стало

- Фиксированное дело с воскресенья 23:00 на 12 часов не занимало понедельник:
  подбор предлагал 09:00 → занятость переносится через границы суток и недели до 11:00.
  Существующее дело не переносится. Полночь — исключительная правая граница интервала.
- Некорректные today/nowTime могли дать предложение в прошлом → некорректные значения
  отклоняются. Длительности предложения округляются так же, как существующий writer.
- «Вернуть» восстанавливало дату, но оставляло новую длительность и лишний перенос →
  восстанавливаются прежние estimateMin, postponedCount и firstDate, включая неизвестную
  длительность. Только действующая квитанция отмены для этого дела; отказ записи оставляет
  перенесённое состояние и квитанцию для повторной попытки.
- При изменении другого дела во время await переносов свежий State становился новым
  снимком, скрывая устаревшее предложение → пакет останавливается. Проверяются остальные
  дела, несвязанные поля перемещаемого дела и фактическое расписание после записи.
  Уже подтверждённый перенос не откатывается; для остатка нужен новый подбор.

- 28 профильных проверок: граница недели/полночь, регулярные интервалы, некорректная дата
  и время, исходные значения после отмены, отказ/повтор, конкурентная правка во время
  успешной и неуспешной записи, обычный последовательный успех.
