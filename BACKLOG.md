## ✅ Решения Альберта 13.08 — готово к исполнению без дальнейших вопросов

> Все пункты отвечены голосом с телефона, детализация уточнена в чате. Каждый пункт ниже — готовая спецификация, не черновик.

- [x] **Q1/Q2 — вечерняя рефлексия вместо алгоритмического «плохой/хороший день».** ⚠️ **Крупная задача, требует отдельного дизайн-прохода — НЕ начинать с наскока.** Альберт прав по существу: судить «плохой ли день» по количеству/времени дел без участия человека нельзя. Решение: заменить/дополнить текущую строку `failure-context-v1` (§4) модалкой, которая появляется, когда человек закрывает последнюю или предпоследнюю задачу дня (не по времени 18:00). Требования из голоса Альберта:
  - Вопросы — через **шкалы** (slider/scale), не текстовые ответы: качество дня, настроение, энергия и ещё что-то — **список шкал ещё не выбран**, Альберт сам сказал «надо подумать, какие вопросы самые полезные для ИИ». Не изобретать шкалы самостоятельно — обсудить с ним отдельным заходом.
  - Внизу — опциональное текстовое ИЛИ **голосовое** (uже есть `voice-input-v1`, подключить туда же) дополнение, с маленькой подсказкой «если есть важные нюансы — допиши или надиктуй».
  - **Ни один пункт не обязателен.** Сколько человек хочет заполнить — столько заполняет.
  - Обязательно должны быть **три исхода**: заполнить / «не сегодня» (спросить снова завтра) / «убрать совсем» (не спрашивать больше). Разное от текущего гейта `pickNudge`, который просто молчит — тут нужна явная память решения.
  - Отдельно (Q2): если человек к 18:00 ничего не отметил, вопрос типа «ты прокрастинировал или был сильно занят?» может быть ОДНИМ из вопросов рефлексии (не отдельным осуждающим тостом) — компрометирующая формулировка сама подталкивает к честному ответу, но НЕ должна сама по себе клеймить день плохим («одно не следует из другого» — его слова).
  - Итог этой фичи затем должен **использоваться в остальных механиках** (по словам Альберта — «выводы про пользователя, использовать в других функциях»), не просто копиться. Это отдельный слой, спроектировать после того, как решены сами вопросы шкалы.

- [x] **Q13 — архивирование и удаление сферы, оба варианта.** Сейчас есть только один режим `delete-skill` (app.js:21117), который **уже не удаляет** связанные квесты/привычки/цели и **не трогает опыт** («Опыт сохранится» — это текст текущего confirm). Нужно два разных действия:

Это близко к текущему поведению «delete», просто без уничтожения объекта сферы.

Технически XP считается не из хранимого леджера, а динамически из `xpEvents()` по завершённым задачам/привычкам/целям — значит «удалить опыт» означает удалить/обнулить сами эти исторические записи для данной сферы, а не только указатель на сферу. Это меняет историю физически — Альберт подтвердил, что при удалении это ожидаемо и нормально, но сформулировать явно в тексте подтверждения («это сотрёт и связанные с ней записи, отменить нельзя»).
