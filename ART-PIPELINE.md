# Satoru — производственный арт-пайплайн (весь путь)

> Как мы реально производим и оживляем всю графику Satoru. Стиль и обоснование — `STYLE-DECISION.md`; здесь — **исполнение от и до**.
> Стратегия (утв. 2026-06-24): **сначала AI-автоматизация (спрайты) для боссов/мобов/питомцев, Rive — позже только для реактивных героев (компаньон/аватар).**
> Принцип: не всё одним путём · сначала видимый результат, потом масштаб · ship по слою (ручеёк).

---

## 0. Карта: что у нас за графика и каким путём

| Категория | Кастом? | Реагирует на данные? | Путь анимации |
|---|---|---|---|
| **Боссы / мобы** (Туман отговорок…) | нет | нет | **A: AI-спрайт-циклы** |
| **Питомцы** (по сферам, морф) | частично | нет | **A: AI-спрайт-циклы** |
| **Эффекты** (level-up, сундук, частицы) | нет | нет | A: AI-спрайты / код-частицы |
| **Комната/Логово, декор, предметы, иконки наград** | сборка из кусков | нет | **Статика** (просто картинки) |
| **Компаньон** (Тень → эволюции) | да | **да** (настроение/связь) | **B: Rive + дата-байндинг** (позже) |
| **Аватар** (игрок) | да (волосы/гир) | да (поза по энергии, билд) | **B: Rive paper-doll** (позже) / пока SVG |

**Три режима оживления:**
- **A — AI-спрайт-анимация:** PNG спрайт-лист (кадры), играется кодом. Автоматизировано, быстро, НЕ реактивно, НЕ кастом.
- **B — Rive-риг:** вектор, дата-байндинг (реагирует на твои данные). Для немногих героев. AI-авто-риг убирает ручной риг.
- **Статика:** просто картинки (комната/декор/предметы), код собирает и подсвечивает.

**Код (zero-dep по максимуму):**
- Режим A → крошечный спрайт-плеер на `<canvas>`/CSS `steps()`. **Без зависимостей.**
- Режим B → рантайм Rive (~200КБ WASM, одна зависимость, само-хост) — грузится **лениво** только на экранах с компаньоном/аватаром.
- Статика → `<img>`/SVG.
→ Зависимость только одна (Rive) и изолирована. Бренд zero-dep почти цел.

## 1. Фаза 0 — зафиксировать стиль (фундамент, один раз)

**Цель:** чтобы ВСЁ, что генерим дальше, было из одного мира (главный риск AI — расхождение стиля).
1. Взять опорный стиль (chibi-explorer реф) + собрать **5–15 консистентных картинок** в этом стиле (реф + догенерить/дорисовать похожие).
2. **Обучить кастом-модель в Scenario** на этом наборе → «Satoru style model». Дальше любой ассет генерим через неё → единый стиль.
3. Зафиксировать палитру, пропорции, толщину линии, **плоский свет** (свет/тени накладываем мы динамически), правила силуэта. (Из `STYLE-DECISION.md`.)

Роль художницы тут: опционально дать пару seed-картинок для обучения. Дальше она НЕ блокер.

---

## 2. Фаза 1 — первый видимый результат: ОДИН босс (пилот пути A)

Конец-в-конец на «Туман отговорок» — проверяем всю петлю на одном, прежде чем масштабировать:
1. **Генерация:** через Satoru-style-model — чистое существо, фронт, плоский свет, прозрачный фон, в полный кадр. (Промпт — §7.)
2. **AI-анимация:** скормить в спрайт-аниматор (Scenario animation / AutoSprite / SpriteFlow) → циклы: **idle** (парение/пульс), **hit** (отдача от удара), **defeat** (рассеивание). Выход: PNG спрайт-лист + сетка кадров (или GIF).
3. **Код (zero-dep):** спрайт-плеер крутит idle; по выполнению задачи → проигрывает `hit`; по победе в рейде → `defeat`-рассеивание. ← закрывает твоё «против чего боролись?» — видимый босс, получающий урон.
4. Вшить в экран рейда/пати.

Это пилот: доказывает режим A на одном ассете. Дальше — масштаб.

---

## 3. Фаза 2 — масштаб режима A: питомцы + мобы + эффекты

Та же петля «генерим архетип → AI-анимирует циклы → код играет»:
- **Питомцы:** idle / happy / sleep. Морф-формы по доминантной под-сфере (разные генерации одного архетипа).
- **Мобы:** idle / hit (для боёв в пати).
- **Эффекты:** level-up-вспышка, открытие сундука — AI-спрайты или процедурные частицы кодом.
Полу-автоматизация: батч-генерация через style-model → курируешь → код играет.

---

## 4. Фаза 3 — статический слой: комната/декор/предметы

- Комната Логова + декор + гир + иконки наград = статичные картинки из style-model (НЕ анимируются).
- Код: собирает комнату из кусков, меняет декор, **свет по времени суток** (наложение), кладёт слои аватар+компаньон+питомцы. (Логово v1 это частично умеет.)

---

## 5. Фаза 4 — реактивные герои через Rive (апгрейд): компаньон → аватар

Только теперь, после дешёвых побед, берём немногих, кто должен реагировать/кастомизироваться.

**Компаньон (Тень):**
1. Генерим персонажа **разобранным на части** (Scenario «separated parts»: голова/волосы/торс/руки/ноги).
2. **AI-авто-риг** (Scenario 2D-rig / godmodeai→Spine) ИЛИ импорт в Rive + авто-риг → скелет почти без ручного.
3. В Rive: **State Machine** — idle / happy / caring / lonely + формы эволюции (Искра→Дух→Страж→Хранитель).
4. **Дата-байндинг:** привязать лицо/позу к переменным Satoru (энергия, bond, настроение). Рантайм Rive играет, приложение лишь **ставит значения** → компаньон реагирует на тебя. Это и есть «присутствие».

**Аватар:** paper-doll (части: волосы/одежда/гир сменные) в Rive ИЛИ пока остаётся SVG-кукла (кастом уже работает), Rive добавляем позже; дата-байндинг позы к энергии, билда к атрибутам.

**Цена:** рантайм Rive = одна зависимость (~200КБ WASM), грузить лениво только на этих экранах.

## 6. Роли и инструменты

| Кто | Что делает |
|---|---|
| **Альберт** | Scenario (обучение стиля + генерация + AI-анимация), курирование, промпты; передача ассетов в кодинг-чат |
| **Художница (опц.)** | пара seed-картинок для обучения модели; по желанию — ручная дошлифовка героев. НЕ блокер, для режима A не нужна |
| **Кодинг-чат / код** | спрайт-плеер (zero-dep), Rive-интеграция + дата-байндинг, сборка комнаты, свет по времени суток |
| **AI-инструменты** | Scenario (генерация + стиль + авто-риг), AutoSprite/SpriteFlow (спрайт-циклы), godmodeai (→Spine) |

### 6.1. Где художница и минимальное ТЗ

В AI-first варианте художница **не блокер и в основном опциональна**. Её роль смещается с «рисовать всё» на **«задать душу мира»**:
- **Главное (Фаза 0): style-seed** — 6–10 эталонных иллюстраций в ОДНОМ стиле → на них учим Scenario-модель → дальше AI сам генерит весь контент в её стиле. Максимальный рычаг: горстка её рисунков = бесконечно ассетов на бренде.
- **Опц.:** ручная дошлифовка/база 1–2 героев (компаньон, аватар) для Rive-фазы, если AI на мягком аниме не держит стиль.
- **НЕ нужна** для: боссов/мобов/питомцев (AI), рига (авто-риг), анимации (AI/код), комнаты/декора (AI).
> Это убирает ровно её боли (риг, воксель, объём): её работа = то, что она любит и умеет — несколько красивых консистентных иллюстраций.

**Минимальное ТЗ (можно слать как есть):**
- **6–10 иллюстраций, ОДИН стиль, одна палитра.** Это эталон, по которому AI потом сам сгенерит остальное.
- Состав (чтобы научить модель миру): 2–3 персонажа (chibi-исследователи, разные), 2–3 существа/питомца, 1–2 предмета/гир, опц. 1 кусочек интерьера.
- Каждая: субъект целиком, фронт или 3/4, **плоский ровный свет** (без драматичных запечённых теней), простой/прозрачный фон, чистая линия.
- Формат: PNG (лучше с прозрачностью) + исходник Procreate/PSD. Разрешение 1024+.
- **НЕ надо:** рига, разбора на части, анимации, множества поз — по одной хорошей позе на ассет.
- Цель ей одной фразой: «ты задаёшь стиль мира — остальное масштабируем AI без тебя».

## 7. Промпты (через Satoru-style-model, плоский свет, прозрачный фон)

**Босс «Туман отговорок»:**
> stylized fog-of-excuses boss creature, soft anime style matching project style, full body, front view, menacing but readable silhouette, swirling smoky body, sly half-lidded eyes, muted grey-violet palette, flat even lighting (no baked shadows), thick clean outline, centered, fully in frame, plain transparent background, game boss sprite

Затем в спрайт-аниматоре задать moveset: `idle` (парение/пульс), `hit` (отдача), `defeat` (рассеивание).

**Персонаж/компаньон под риг:** см. `STYLE-DECISION.md` (A-поза, руки от тела) + отдельный заход «separated into parts».

## 8. Честные реалии
- Scenario/AutoSprite — платный SaaS; обучение кастом-модели имеет кривую входа; нужен хороший seed-набор для консистентности.
- AI-спрайты для мягкого аниме — качество скачет, закладывай итерации.
- Rive = одна зависимость + кривая рига (смягчена авто-ригом).
- **Image-to-video НЕ используем** для игровых ассетов (тяжело, стиль плывёт, не интерактивно) — только для разовых маркетинг-клипов.

## 9. Порядок (что за чем)
1. Фаза 0 — стиль + обучить Scenario-модель.
2. Фаза 1 — **пилот: один босс** конец-в-конец (генерация → AI-анимация → спрайт-плеер → экран рейда). ← первый видимый выхлоп.
3. Фаза 2 — масштаб A: питомцы, мобы, эффекты.
4. Фаза 3 — статика: комната/декор/предметы.
5. Фаза 4 — Rive-апгрейд: компаньон (дата-байндинг) → аватар.

Каждый шаг: ship → пощупать → следующий. Арт-трек идёт **параллельно** v1-балансу; оба втекают в одно приложение.
