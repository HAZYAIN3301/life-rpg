## 0. Что это и чего тут нет

Движок отвечает на два вопроса: **случилось ли что-то, ради чего стоит вмешаться**, и **какой ровно один ход предложить**. Он не рисует, не исполняет действие и не решает, как это назвать словами.

Здесь намеренно нет ИИ. Выбор хода не должен зависеть от наличия ключа, лимита или настроения модели. ИИ может позже переписать формулировку выбранного хода — но не выбрать его и не отменить.

## 1. Что нужно подключить со стороны UI

Модули лежат в `public/`, но **в `index.html` и в SHELL `sw.js` их добавляет UI-агент** — эти файлы его. Порядок обязателен, роутер зависит от событий:

```html
<script src="secretary-events-v1.js?v=..."></script>
<script src="secretary-router-v1.js?v=..."></script>
<script src="commitment-v2.js?v=..."></script>
```

В `sw.js` — `'secretary-events-v1.js', 'secretary-router-v1.js', 'commitment-v2.js'`
в `SHELL` + бамп `CACHE`.

`commitment-v1.js` остаётся подключённым: он не удалён и не изменён.

Сервер уже подключает оба через `require`, для него ничего делать не нужно.

## 2. Эндпоинты

### `GET /api/secretary`

Возвращает **один ход или молчание**. Молчание — норма и приходит чаще хода.

Заголовки (иначе сервер посчитает день по UTC и промахнётся мимо утра):

| Заголовок | Значение | Пример |
|---|---|---|
| `X-Local-Day` | локальный день пользователя | `2026-09-02` |
| `X-Tz-Offset` | сдвиг от UTC в минутах | `120` |

```json
{ "offer": null }
```

```json
{
  "offer": {
    "offerId": "morning-after-overrun|2026-09-02|attention.escaped|2026-09-01|tiktok",
    "capability": "morning-after-overrun",
    "action": "recovery_day_open",
    "channels": ["card", "push"],
    "confidence": 0.9,
    "askOnly": false,
    "reason": "escaped",
    "about": { "day": "2026-09-01", "eventKey": "attention.escaped|2026-09-01|tiktok" },
    "quote": { "id": "c2", "title": "Подъём в 7:00", "win": "успеваю до школы" },
    "cooldownKey": "morning-after-overrun|2026-09-02"
  }
}
```

**`422 invalid_secretary_state`** — файл повреждён. Показывать ошибку и путь восстановления, **не** пустое состояние: пустое означало бы «ничего не случилось».

### `POST /api/secretary/event`

Сообщить факт. Тело — см. §3.

```json
{ "ok": true, "added": true }
```

`added: false` — **не ошибка**, а нормальный повтор (retry, второе устройство). Ответ 200, повторять не нужно.

### `POST /api/secretary/offer`

Отметить исход хода. Обязательно вызывать — иначе cooldown не сработает и предложение вернётся.

```json
{ "cooldownKey": "morning-after-overrun|2026-09-02", "state": "dismissed" }
```

`state` ∈ `offered | accepted | dismissed`. Другое → `400 bad_state`.

## 3. Словарь событий

`SecretaryEventsV1.TYPES`:

| Тип | Когда слать | Доп. поля |
|---|---|---|
| `attention.overran` | окно внимания закончилось позже своей границы | `plannedMinutes`, `actualMinutes` |
| `attention.escaped` | человек сам отметил «меня унесло» | — |
| `evening.late` | активность позже согласованного вечернего времени | `minutesPast` |
| `day.silent` | **подтверждённо** пустой день | `silentDays` |
| `morning.open` | первое открытие в новом дне | — |
| `day.closed` | человек закрыл день сам | — |
| `offer.dismissed` / `offer.accepted` | исход предложения | `capability` |

Обязательные поля: `type`, `day` (`YYYY-MM-DD`). Опционально `at` (ISO), `source` (`client|server|extension|native`), `ref` (до 60 символов — что именно, например `tiktok`).

**Что слать нельзя:** URL, поисковые запросы, текст страниц, названия чужих людей. Модуль такие поля просто отбросит, но правило — продуктовое, а не техническое.

**Ключ идемпотентности** = `type|day|ref`. Гранулярность дневная: два превышения за день — один повод вмешаться, потому что человеку нужен один разговор, а не два одинаковых.

## 4. Как показывать ход

### Обязательные правила

- **Один ход на экране.** Второй по приоритету не показывается «заодно». Метрика: поверхностей ≤1, параллельных предложений ≤1.
- **`askOnly: true` → это вопрос, не план.** Формулировка обязана спрашивать об одном факте, а не утверждать что-то о человеке. Приходит при `confidence < 0.6` — сейчас это `reason: "silent"`.
- **`quote` может быть `null`.** Тогда показывается вариант без цитаты. Выдумывать «твоё решение» запрещено: смысл цитаты в том, что это его собственные слова из ресурсного состояния.
- **`quote` теперь выбирается под занятие.** Если у человека есть уговор вида `attention` с ярлыком, совпавшим с `ref` события, цитируется он, а не якорь подъёма. Порядок: совпавший `attention` → любой `attention` → `anchor` → `edge` → первый живой.
- **Архивные уговоры больше не цитируются.** Это была ошибка: фильтр проверял несуществующее поле `archived` вместо `archivedAt` и не отсеивал ничего, поэтому человеку показывали как действующее то решение, от которого он уже отказался. Если UI где-то опирался на прежнее поведение — оно изменилось намеренно.
- **Ни диагноза, ни стыда, ни счёта.** Слова «срыв», «провал», «ты снова» недопустимы. Ни XP, ни золота, ни серии — ход ничего не начисляет и не отнимает.
- **Dismiss обязателен как равноправная кнопка**, а не как крестик в углу. Отказ — это данные о неуместности.

### `reason` → о чём речь

| `reason` | Что произошло | confidence |
|---|---|---|
| `escaped` | сам отметил «меня унесло» | 0.9 |
| `overran` | измеренное превышение границы | 0.8 |
| `late` | поздняя активность | 0.7 |
| `silent` | тихий день — **только вопрос** | 0.4 |

### `action` → что открыть

| `action` | Поверхность |
|---|---|
| `recovery_day_open` | День восстановления |
| `rest_start_prepared` | заранее подготовленный отдых |
| `evening_transition_open` | вечерний переход |
| `ask_one_question` | один вопрос, без плана |

Словарь закрытый и короткий. Разрушительного, платёжного, социального и публикационного в нём нет и не появится — это проверяется тестом.

## 5. Утренний перехват: почему именно он первый

В разборе 01.09 разделены два разных провала:

1. **Вечерний** — отдых без конца, финиш в три ночи. Ресурса ноль, вмешательство почти недостижимо.
2. **Утренний** — человек проснулся и **осознанно решил списать весь день**: «лучше насытить по максимуму и играть весь день».

Второй дороже: превращает одну плохую ночь в два потерянных дня. И он достижим — решение принимается на свежую голову и проговаривается словами.

Поэтому единственная capability в Lite-версии срабатывает **утром (05:00–13:00 по местному времени) и только при вчерашнем поводе**. Без повода не срабатывает никогда: предложить День восстановления просто так — значит объявить день плохим за человека.

Cooldown — раз в локальный день, и он общий для `accepted` и `dismissed`.

## 6. Что движок ждёт от UI

1. Слать события из тех мест, где они рождаются: конец окна внимания, вечерняя активность, закрытие дня, первое открытие.
2. Вызывать `POST /api/secretary/offer` **всегда** — и на принятие, и на отказ.
3. Не показывать второй ход, даже если первый отклонён: до завтра тишина.
4. На `422` — экран восстановления, не пустое состояние.

## 6b. Массовые операции: резолвер → предпросмотр → откат

Три модуля, закрывающие «Джарвис с массовыми операциями». Все чистые, все без сети.

### `GoalResolveV1` — фраза в id

```js
const r = GoalResolveV1.resolve('убери все цели Jugend Forscht', State.goals);
// { tokens, strong: [{id,title,score,archived}], weak: [...], ambiguous: bool }
GoalResolveV1.preselectIds(r);   // только strong
```

**Правила для UI:**

- `strong` можно отметить галочками заранее, `weak` — показать, но **не отмечать**. Цена ошибки несимметрична: лишний кандидат стоит двух секунд, тихо задетая цель — потери из виду.
- `ambiguous: true` означает «уверенных совпадений нет». Тогда спрашиваем, а не действуем.
- Архивные цели остаются в выдаче с флагом `archived` — исчезать они не должны.
- Порядок стабилен: список не перетасуется между показом и подтверждением.

### `BulkUndoV1` — транзакция

```js
const plan = BulkUndoV1.plan({ op: 'archive', ids, items: State.goals });
// { planId, affected:[{id,title,from,to}], skipped:[...], missing:[...] }

const res = BulkUndoV1.apply(State.goals, plan, nowIso, appliedPlanIds);
// { items, undo:{token,planId,at,restore}, applied, reason }

const back = BulkUndoV1.undo(items, res.undo, token, nowIso);
// { items, undone, reason }
```

Операции: `archive | unarchive | pause | resume`. Разрушительных нет и не будет.

**Правила для UI:**

- Показывать **все три списка**: что изменится, что уже в нужном состоянии, и `missing` — id, не найденные среди своих. `missing` не отменяет операцию, но человек обязан их видеть: это признак, что список собран неверно.
- `applied: false` с `reason: 'already_applied'` — повтор, а не ошибка. Ответ спокойный, без «не удалось».
- `reason: 'nothing_to_do'` — тоже не ошибка: всё уже в нужном состоянии.
- Кнопка отката живёт **30 минут** (`UNDO_TTL_MS`). После — `reason: 'expired'`, и это надо сказать вслух: молчаливое «ничего не произошло» оставит человека уверенным, что он откатил.
- Пачка ограничена **50** объектами: список, который нельзя прочитать глазами, не является предпросмотром.

`BulkUndoV1.auditEntry(plan, res, nowIso)` даёт запись для журнала — что произошло, без копирования заголовков объектов.

### Полный поток

```
фраза → GoalResolveV1.resolve → человек правит галочки
      → BulkUndoV1.plan → предпросмотр трёх списков
      → подтверждение → BulkUndoV1.apply → тост с «Отменить»
      → BulkUndoV1.undo по токену
```

Ассистент участвует только на первом шаге. Ни `plan`, ни `apply` он не вызывает сам.

### `RestProfileV1` — рецепты отдыха

```js
RestProfileV1.pickForLowResource(profile, { avoidId, preferOffline });  // ОДИН рецепт или null
RestProfileV1.entryEase(recipe);   // 0..1, дешевизна входа
RestProfileV1.needSetup(profile);  // рецепты с дорогим входом
```

**Правила для UI:**

- При истощении показывается **один** рецепт, не список: стоимость выбора — часть проблемы.
- `null` означает «рецептов нет». Тогда предлагаем настроить один за две минуты, а не выдумываем отдых.
- Поле `setup` — главное: что готово заранее. Рецепты без него видны через `needSetup` и чинятся в спокойный момент, а не в момент истощения.
- Цифровой отдых не помечается плохим. `preferOffline` — предпочтение, не запрет.
- На выходе спрашиваются **четыре независимых** вопроса: закончил у границы / было ли приятно / стало лучше-так же-хуже / осталось ли сожаление. Схлопывать их в один нельзя: «вовремя закончил» и «восстановился» — разные факты.

## 6c. `CommitmentV2` — уговор про внимание

Новый файл рядом со старым. **`commitment-v1.js` не изменён**: его двадцать тестов продолжают проверять его же, а старые данные читает старый проверенный код.

### Что добавилось

| Что | Значение |
|---|---|
| `KINDS.attention` | граница конкретного занятия, решённая заранее |
| `edge.kind: 'duration'` | `{ kind: 'duration', minutes: 12 }` — 1..600 |
| `target` | ярлык занятия, только у `attention`, ≤40 символов |

Пример уговора, ради которого вид и заведён:

```js
CommitmentV2.add(state, {
  id: 'a1', kind: 'attention',
  title: 'TikTok — только выложить ролик',
  win: 'вечер остаётся мой',
  target: 'tiktok',
  edge: { kind: 'duration', minutes: 12 },
});
```

`edge` вида `time`/`window` описывает границу дня, `duration` — границу занятия. «Двенадцать минут» не выражается ни временем суток, ни окном, поэтому без этого вида решение владельца просто не записывалось.

### Миграция

```js
const { state, migrated, dropped } = CommitmentV2.migrate(rawFromDisk);
```

- Схема v2 — надмножество v1, поэтому в норме `dropped` пуст.
- Журнал переносится **без перевода значений**: словарь остался `'win' | 'miss'`. Перевод в булевы стёр бы всю историю отметок при первом же чтении реального файла.
- `core`, `decidedOn`, `budget`, `archivedAt`, `modes` сохраняются полностью. Потеря `budget` порвала бы серию молча.
- Идемпотентна: на состоянии v2 возвращает `migrated: false` и то же состояние.
- Испорченная запись попадает в `dropped` с причиной (`invalid` / `duplicate`), а не исчезает молча.

**Сервер мигрирует при чтении и НЕ пишет обратно.** Запрос на чтение не меняет данные, а нетронутый v1-файл — страховка на случай ошибки в самой миграции. Файл переходит в v2 только когда его перезапишет UI.

### `bestFor` — кого цитировать

```js
CommitmentV2.bestFor(state, 'tiktok');            // среди всех живых
CommitmentV2.bestFor(state, 'tiktok', day, mode); // с учётом режима дня
```

Сравнение ярлыков точное (регистр не важен). Угадывать «похожие» занятия нельзя: иначе человеку предъявят его решение про одно как решение про другое. Возвращает `null`, когда живых уговоров нет.

### Правила для UI

- **Выигрыш обязателен и у `attention`.** Форма не должна давать сохранить границу без него: граница без названного выигрыша производит вину, а не движение.
- **`target` — ярлык, который человек ввёл сам.** Не подставлять туда URL, домен или что-либо, прочитанное с экрана. Модуль обрежет, но правило продуктовое.
- **Ничего не начисляется и не отнимается.** У `attention` нет XP, золота и штрафа за нарушение — как и у остальных видов.
- **Не блокировать.** Граница — это когда приложение замолкает, а не когда не пускает.
- Остальной API совпадает с v1 один в один (`dueOn`, `coreOf`, `extrasOf`, `mark`, `clearMark`, `streakOf`, `unsettled`, `dayScore`, `setMode`, `archive`). Тест `commitment-v2.test.js` сверяет результаты обоих модулей на v1-данных по каждой общей функции — это защита от расхождения копий.

## 8. Чего движок не сделает

- Не решит, какими словами говорить: копирайтинг за UI.
- Не заблокирует чужое приложение: это адаптеры R3–R5.
- Не определит усталость по числу задач — `confidence` честно низкая там, где данных нет.
- Не назовёт молчание срывом ни при каких условиях.
