## 1. Дверь №1 «уговор про внимание»: и лишняя, и сегодня невозможная

**Лишняя.** Границу «в TikTok только выложить, двенадцать минут» человек **уже объявляет** —
в правиле Attention: приложение/сайт, зачем входишь, сколько времени, что должно остаться
после выхода. Это те же четыре поля, что у `attention`-уговора:

| Уговор | Правило Attention |
|---|---|
| `target` | `policy.name` — «TikTok» |
| `edge: { duration, minutes }` | `purpose.defaultMinutes` |
| `win` | `purpose.outcome` — «Выложен один ролик» |
| `title` | выводится из первых двух |

Вторая форма = второе место рождения одного факта. Правильный ход — не спрашивать заново, а
**вывести уговор из правила**, которое человек уже заполнил.

**Невозможная сегодня.** Проверено исполнением, не чтением:

```
validateCommitmentState с attention-уговором: false
он же с обычным уговором v1:                  true
```

- `commitment-store-v1.js` — валидатор записи, общий для клиента и сервера — знает пять
  видов (`step, edge, moment, anchor, care`) и сверяет ключи через `exactKeys` без `target`.
- Он же знает четыре вида границы (`none, time, window, trigger`). `duration` отвергается.
- Хуже: `commitment-v1.js:138` возвращает `null` на незнакомый вид, а `CommitmentV1` стоит
  на пути **каждой** операции с обязательством квеста (`takeQuestCommitment`,
  `completeTask`, откат галочки). То есть первый же уговор, взятый по квесту, **молча стёр
  бы** записанную границу внимания.

**Порядок работ, если дверь всё-таки нужна:** валидатор на шесть видов и на `duration` →
клиентские пути с `CommitmentV1` на `CommitmentV2` → и только потом любая форма.

## 2. `first-value-v1` станет третьим движком первого результата

В приложении **уже два**, оба работающие:

- **Опросник онбординга** — один ответ превращается в цель плюс первый шаг, и шаг
  коммитится квестом с датой «сегодня» (`app.js`, `/api/questionnaire/commit`). Это ровно
  «довести до первой настоящей ценности».
- **Гид, первая глава `first-journey`** — ведёт по шагам `first-task-create` →
  `select` → `focus` → `complete` → `reward`. Это тоже она.

Третий движок принесёт своё состояние (`Store.saveNow('first-value', …)`), свои маршруты и
свой `targetMs`. На «Сегодня» его `primaryAction` встанет рядом с целями Гида — и получится
ровно тот дефект, который сегодня чинили на этом же экране: **два блока, объявляющих себя
главным ходом**, каждый по-своему правый.

Решать Альберту, но решать **до** постройки: три состояния одного пути не сведутся потом.

## 3. `ai-memory-policy-v1` встанет второй памятью рядом с существующей

Настройки → Связи уже содержат карточку **«🧠 Что Тень о тебе помнит»** — свободный текст на
пять разделов (`profile-memory-v1`), который Тень берёт с собой в каждый разговор и который
человек правит руками.

Промпт прямо говорит «не трогай её и не смешивай с записями». Тогда в одних настройках
окажутся две поверхности, обе отвечающие на вопрос «что приложение обо мне помнит», и правка
в одной не меняет другую. Новый API даже возвращает `legacy: {text, updatedAt, auto}` — то
есть движок про старую запись знает.

**Минимум, чтобы это не стало вторым местом рождения:** две поверхности не могут обе
называться «что Тень помнит». Либо структурные записи — источник, а свободный текст —
собранное из них представление, либо у них разные, честно разные названия и человек видит,
чем они отличаются.

## 4. Телеметрия: задача верная, и она хуже, чем описана

`track(event)` шлёт `POST /api/analytics` **всегда**, без единой проверки согласия:

```js
function track(event) { … fetch('/api/analytics', { method:'POST', … }); }
```

То есть сейчас это не «opt-out», а сбор вообще без спроса. Экран нужен, и приоритет верный.

Одно замечание по связности: после него согласий станет пять и все в разных местах —
публикация в рейтинге, вклад в пати, синхронизация Attention, факты для ассистента и
телеметрия. Сводить их в один экран **не надо** (это разные данные и разные получатели), но
они обязаны выглядеть и называться одинаково, иначе человек не узнаёт в них одну и ту же
вещь. Образец уже есть — карточка согласия на публикацию в Рейтинге: заголовок, что именно
видно, что не публикуется, одна кнопка, состояние словами.
