# Контракт: association-файлы платформ и `/api/version`

> Срез B1+B5 из APPLE-PRE-PAYMENT-PLAN-2026-09.md. Построено 14.09 до оплаты
> Apple Developer Program. Модуль `public/native-association-v1.js`,
> тесты `scripts/native-association-v1.test.js`, маршруты в `server.js`.

## Зачем

Universal Links на iOS и App Links на Android работают только если origin отдаёт
файл, доказывающий связь домена с приложением. Оба файла тянут платформенные CDN
и **кэшируют ответ**. Поэтому сломанный документ со статусом 200 хуже
отсутствующего: платформа запомнит поломку и перестанет спрашивать.

Идентификаторы приложений не существуют до оплаты. Значит они не могут быть
в коде — иначе к моменту оплаты понадобится релиз. Они приходят переменными
окружения, и после оплаты нужен только рестарт сервиса.

## Маршруты

`GET|HEAD /.well-known/apple-app-site-association` и
`GET|HEAD /.well-known/assetlinks.json`.

Объявлены до auth, recovery и статики. Поэтому query не меняет ответ, сессия
не требуется, и никакой файл в `public/.well-known/` не может подменить документ.

- Настроено и валидно → `200`, `Content-Type: application/json` **без charset**
  (Apple исторически отказывался читать файл с параметром charset),
  `Cache-Control: public, max-age=3600`.
- Не настроено → `404`.
- Настроено, но не проходит валидацию → `404` плюс строка в лог сервера
  с названием причины. Частичный документ не отдаётся никогда.
- Другой метод → `405`.

`GET|HEAD /api/version` отвечает без сессии, `Cache-Control: no-store`:
имя приложения, версия shell (читается из `sw.js` при старте), commit из
`RAILWAY_GIT_COMMIT_SHA` если провайдер его дал, текущее время сервера и
плоский список возможностей. Нативный клиент едет через App Review и отстаёт
от сервера на недели — он должен спросить, а не угадывать по дате своей сборки.
Возможности отражают факт: `deviceSessions` сейчас `false`, потому что токенов
устройства ещё нет. Секретов, счётчиков и персональных данных в ответе нет.

## Переменные окружения

| Переменная | Пример | Когда |
|---|---|---|
| `APPLE_APP_IDS` | `ABCDE12345.app.satoru.ios` | после оплаты, Team ID берётся из Apple Developer |
| `APPLE_APPLINK_PATHS` | `/gate/* /return/*` | необязательно; по умолчанию `/*` |
| `ANDROID_PACKAGE` | `app.satoru.android` | при сборке подписанного APK |
| `ANDROID_CERT_SHA256` | `AA:BB:…` (32 байта) | вместе с `ANDROID_PACKAGE` |

Списки разделяются пробелами, запятыми и переводами строк: значение, вставленное
в панель хостинга, приносит невидимый пробел.

## Что модуль отказывается принять

- Team ID не ровно из десяти символов `[A-Z0-9]`; в нижнем регистре тоже отказ —
  Apple печатает их прописными, и тихо апперкейсить чужой идентификатор нельзя.
- Bundle ID из одного сегмента или с недопустимым символом.
- Один плохой элемент в списке отменяет **весь** документ, а не только себя.
- Путь без ведущего слэша.
- Android-пакет без отпечатка сертификата: пустой `sha256_cert_fingerprints`
  ничего не доказывает и молча ломает тот самый app link, ради которого файл есть.
- Отпечаток не из 32 байт. С двоеточиями и без — принимается, регистр нормализуется.

## Границы

- Домен пока не куплен. Маршрут готов, содержимое AASA появится вместе с доменом
  и Team ID; до этого оба файла честно 404.
- На реальном устройстве ничего не проверено: у агента нет ни подписи, ни
  симулятора, ни iPhone. Universal Link требует проверки из состояний
  already-installed, cold-start и logged-out — это после оплаты.
- Файл отдаётся, но это не доказывает, что Apple его примет: CDN Apple тянет
  документ сам, и проверить это можно только с настоящим App ID.
- `webcredentials` включён теми же идентификаторами. Это включает ассоциацию
  автозаполнения паролей и passkeys с этим origin. Отдельная работа по passkeys
  не сделана; ключ лишь не требует второго файла и второго деплоя позже.
