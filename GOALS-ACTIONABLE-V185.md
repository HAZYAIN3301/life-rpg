# Goals actionable v185

## Почему понадобился ещё один проход

Goals v169 убрал стену всех горизонтов с первого экрана, а v184 вернул массовое управление. Но выбранную цель всё ещё было трудно **закончить или начать**: достижение пряталось в управлении, пустой импорт оставлял карточку без следующего шага, описание уступало место вторичной структуре, а плоский picker сфер визуально стирал иерархию и авторские цвета.

## Контракт экрана

- `Сейчас` показывает до трёх ближайших активных проектов/целей. У каждой строки справа есть отдельная 42 px галочка достижения — это не вход в настройки и не скрытое меню.
- Галочка ожидает единую проверенную запись `goals/tasks/groups`. При ошибке цель остаётся активной; false-success и предварительной выдачи XP нет.
- В detail сначала идут название, описание, состояние, сферы, явное `Цель достигнута` и следующий шаг. `План`, `Контекст` и `Управление` раскрываются только по запросу.
- Если у старой цели нет ни незавершённого пункта, ни связанного квеста, блок `Следующий шаг` сразу предлагает короткое поле и создаёт связанный квест на сегодня. Пустая цель больше не заканчивается сообщением-тупиком.
- Термин `Инициатива` в пользовательском интерфейсе заменён на понятный `Проект`. Внутренние `goalGroups` и устойчивые id не переименованы, поэтому данные и ссылки не мигрируют и не ломаются.
- Проекты в `Все цели` и горизонты в `Карте` — сворачиваемые секции. Это progressive disclosure, а не ещё одна сетка одинаковых карточек.

## Сферы цели

- Одна цель и один квест могут иметь несколько **основных** сфер и до трёх **фоновых**.
- Основная сфера означает прямой результат цели; фон — сферу, которую действие поддерживает попутно. Фон не получает скрытый второй XP.
- Picker сохраняет N-уровневый путь, показывает авторский цвет каждой сферы и даёт отдельные 42 px действия `Выбрать` / `+ Фон`.
- Поиск работает по полному пути. Выбор не превращается в стену одинаковых cyan-овалов и не смешивает столбы с подсферами на одном визуальном уровне.
- Старые записи с одним `skillId` остаются валидными. Новые поля `skillIds` и `backgroundSkillIds` опциональны на сервере.

## AI-импорт

Новый контракт просит модель вернуть не пустые карточки, а проверяемый граф:

- проект, горизонт и parent-связь;
- краткое описание;
- точные существующие основные и фоновые сферы;
- 2–7 последовательных шагов для checklist-цели;
- до трёх конкретных ближайших действий по 5–60 минут для leaf-целей;
- дедлайн и честную числовую метрику только там, где она действительно числовая.

Принятие предложений одной транзакцией сохраняет `goals + tasks + groups`. Ошибка откатывает все три массива. Уже существующие пустые цели не переписываются молча моделью: для них есть явный быстрый следующий квест в detail.

## Visual QA

- Desktop `1280×900`: detail, строка цели, несколько основных/фоновых сфер; отдельная галочка достижения; horizontal overflow 0.
- Mobile `375×812`: picker работает как нижняя панель, не расширяет body, все role-buttons не меньше 42 px, список прокручивается независимо.
- Dark UI проверен живьём; цвет каждой сферы остаётся смысловым, общий accent используется только для системных действий.
- Art-деревья не затрагивались.
