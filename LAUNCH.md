## 🔴 (исходная инструкция) персистентный том на Railway

**Проблема.** Файловая система контейнера Railway **эфемерна**: при каждом редеплое/рестарте всё в `data/` стирается — пользователи, их данные, пати, ключ Web Push (`push-vapid.json`), сессионный секрет (`secret.json`), фидбек. Без тома любой деплой = потеря всех аккаунтов и разлогин всех.

**Как исправить** (5 минут в дашборде Railway):
1. Railway → проект → сервис `life-rpg`.
2. **Variables** → добавить переменную: `DATA_DIR` = `/data`
   *(сервер уже читает `process.env.DATA_DIR` — код менять не надо).*
3. Сервис → **Volumes** → **+ New Volume** → Mount path = `/data` (должен совпадать с DATA_DIR), привязать к сервису `life-rpg`.
4. **Redeploy**. Теперь всё под `/data` переживает деплои.
5. **Проверка:** сделай тестовый редеплой → существующие аккаунты/данные на месте, push-подписки и сессии не сбросились.

⚠️ **Важно про переход:** том монтируется ПУСТЫМ. На том деплое, где добавляется том, текущие прод-данные (albert/viola и пр.) «исчезнут» — приложение начнёт читать из пустого `/data`. Это разово. Варианты:
- **Просто:** делаем это сейчас (пре-альфа), принимаем разовый сброс, дальше данные вечны. Albert/Viola перерегаются.
- **Без потерь:** до монтирования скачать текущие `data/*` (через админку/SSH) и залить на том. Сложнее; для пре-альфы не обязательно.

→ Сделать **до** того, как придут реальные юзеры.
