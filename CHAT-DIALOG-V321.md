## Исправлено

- Выбранная неделя собирается заново из State.tasks при каждом сообщении, включая
  статусы, completedAt, постоянное расписание, текущие локальные дату/время/часовой пояс.
  Прежний снимок при открытии не используется как источник статусов.
- При контекстном обсуждении не добавляется конкурирующая сводка последних 7 дней.
  Живой контекст идёт перед длинным справочником приложения, чтобы серверный предел
  системного сообщения не отрезал его после справочника.
- Инструкции: не считать прошедшую дату/намерение/XP/свой старый ответ доказательством
  выполнения; отсутствие отметки не означает доказанный пропуск. Поправки человека
  важнее старого плана. Сверка по запросу без самовольного нового расписания; до 100 слов
  обычно, один недостающий вопрос; никаких предложений в прошлое.
- Footer: дополнительные инструменты и пояснения под «Ещё». Информация об отправке
  файлов остаётся рядом с выбором файла. Недоступный голосовой вызов не занимает строку;
  голосовой статус виден только при активном прослушивании или ошибке.
- Сбой запроса — компактный статус без озвучки. Повтор того же вопроса использует
  одну реплику пользователя. Служебные ошибки и неотвеченные вопросы не подмешиваются
  в историю провайдера. HTTP с не-JSON телом сохраняет код (например 502), а не
  маскируется под потерю сети при JSON.parse. Текст возвращается в поле ввода.
