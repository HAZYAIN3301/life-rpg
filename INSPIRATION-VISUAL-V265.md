# Вдохновение v265: личный вкус, настоящие изображения и короткие эдиты

Запрос владельца: материал должен попадать в индивидуальный стиль каждого человека.
Пять присланных Pinterest-пинов — примеры композиции, пространства и настроения,
а не универсальные предпочтения всех аккаунтов. Старые trailers/AMV не заменяют
нужные находки. Этот контракт описывает интеграцию пакетов MEDIA/TASTE-V262;
номер релиза v265, поскольку master уже содержит независимые v262–v264.

## Пользовательский путь

В настройке есть личные темы, форматы, свободное описание визуального вкуса,
до десяти Pinterest/TikTok/YouTube-референсов с названием и объяснением.
Подписи и превью конкретных Pinterest/TikTok постов разрешаются сервером через
официальные metadata endpoints. Это не анализ пикселей и не vision-модель:
при бедной подписи полезно дописать, что именно нравится на изображении.

Подборка показывает до трёх материалов в день. Изображение/постер идёт первым,
подпись и источник — под ним. Есть видимые «Понравился стиль» и «Не мой стиль»;
оценка и объяснение учитываются в следующих подборках. Ключевые слова, имена,
визуальные мотивы и теги влияют на отбор вместе с темами; разнообразие форматов
не вытесняет явно более подходящее фото. При конкретном описании визуального
стиля фото/эдит должны совпасть с мотивом в настоящем названии/тегах/keywords;
одна общая тема не заполняет пустое место. Отрицательная оценка описанного мотива
позволяет пробовать другой стиль через существующее обучение. Собственные референсы исключаются из
новых находок. История показов ограничена 180 записями, повторный показ подавлен
на 45 дней. Подтверждённый день, включая пустую подборку, не перетасовывается
после reload или feedback. Сохранённое остаётся отдельным разделом.

## Поставка

`inspiration-visual-batch-v1.js` содержит 17 конкретных постов с официальными
превью: 14 Pinterest и 3 TikTok. Метаданные всех 17 повторно получены 19.09.2026.
Наличие metadata не выдаётся за ручную оценку художественного качества или
успешное проигрывание. Превью удалённые; медиа не скачиваются и не перепубликуются.
AI-коллаж из примеров подписан как коллаж, а не достоверная фотография животного.

Автоматический поиск включается отдельно в личной настройке. Сервер использует
существующий `BRAVE_SEARCH_API_KEY`, до двух запросов за UTC-день и до трёх
новых результатов за локальный день. Запрос строится из одного конкретного
референса или описания вкуса, без смешивания всех несвязанных примеров.
Поиску уходят только явно записанные слова вкуса: без userId, IP, истории,
целей, исходных URL и cookie. Ключевые слова результата берутся из настоящей
подписи результата, а не из поискового запроса. Источник — конкретный pin/video,
не выдача поиска и не лента. TikTok posters дополнительно разрешаются через
официальный metadata endpoint.

Без ключа сервис сообщает `unconfigured`, UI объясняет доступность только каталога.
Ошибка провайдера не превращается в фиктивный успех поиска. Неактуальный или
нечитаемый cache не заменяется молча пустым; резерв лимита сохраняется до сети.
Повтор ограничен сохранённым дневным результатом. Глобальный живой поиск требует
проверки реальной конфигурации и entitlement Brave Image/Web Search на production.

⚠️ Ломающее изменение допуска поставки: `checkMethod:'metadata'` теперь разрешает
конкретные Pinterest/TikTok материалы с `available:'unknown'`. Это **кандидат на
просмотр**, а не playback receipt. Для других внешних видео прежний playback gate
сохранён. Неизвестный язык визуального поста не объявляется «без слов».
`tags`, `keywords`, размеры превью и `mediaType` доходят через policy до UI.

## Проигрывание

Статичные Pinterest-изображения увеличиваются в отдельном native dialog внутри
Satoru: без внешнего iframe, с Escape и возвратом фокуса. Неизвестный тип остаётся
превью поста. Плеер создаётся только явным нажатием. Допускается официальный embed точного
поста; URL/source id и параметры валидируются. Один плеер за раз, без autoplay
и loop. TikTok `rel=0` сам по себе не выключает рекомендации: iframe удаляется
по проверенному ended/error, таймауту, закрытию и выходу с экрана/аккаунта.
Проверяются origin и окно отправителя сообщения. Ошибка даёт понятный статус
и возможность повторить/открыть конкретный источник; загрузка iframe не отмечает материал просмотренным.
Истёкший TikTok poster можно обновить через metadata, не подменяя его видеофайлом.

## Владелец записи

`POST /api/inspiration/profile` принимает только нормализованные `base`, `profile`,
`finds` (до трёх), опционально точный `baseDraft`. После чтения всего тела сервер
читает актуальные settings/tasks, сравнивает профиль и черновик и записывает
через существующий общий WAL. Независимые настройки и задачи сохраняются.
Обычный settings PUT не используется для подтверждения подборки/feedback.

Успех — только typed receipt:
`{ok:true,kind:'inspiration-profile',version:1,replay,snapshots:{settings,tasks}}`.
Повтор после потерянного ответа идемпотентен; другой вкус/история/новый draft дают
409. Client account/epoch/generation guards отменяют поздние ответы. До квитанции
новая подборка скрыта, ошибка предлагает повтор того же результата.

`settings.inspirationFinds` — массив до 120 безопасно очищенных кандидатов.
Новая metadata заменяет старую только при более свежем `lastCheckedAt` под CAS;
поздний ответ не откатывает свежую. Нельзя объявить playback/доступность через
клиентский payload. Discovery ledger — отдельный server-owned
`inspiration-discovery.json`, закрытый от generic data/restore.
`POST /api/inspiration/metadata` требует сессию, тело до 8 KiB, до 20 запросов/мин
на аккаунт; отменяет upstream при отключении клиента. Cookie/Bearer владельцы
используют существующие правила сессий v264.

## Проверки и публикация

Целевые тесты проверяют URL/message validation, taste/reference matching,
историю/пустой день, owner receipt, CAS/черновик/повтор, rollback/SIGKILL общего WAL,
разделение аккаунтов, лимиты/отмену, provider ошибки и обновление metadata.
Итоговые browser, full-suite и production receipts — в верхней записи DEVLOG.
Подключены browser modules в index/SHELL; CACHE и PWA version `satoru-v265`.

Старый Railway URL должен работать наряду с `satoruapp.com` — текущие сессии и
расширение от него зависят. Этот релиз не меняет их адрес и сессии устройств v264.
