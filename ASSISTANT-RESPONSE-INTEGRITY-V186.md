# Assistant response integrity v186

## Инцидент

В длинном личном сообщении человек попросил Тень подробно разобрать накопившуюся усталость и прийти к решениям на вечер. Ответ выглядел нормальным в начале, но закончился буквально на `2. **`. UI убрал индикатор ожидания и показал фрагмент как готовый совет.

## Причина

- `/api/ai/chat` давал модели только `1500` output tokens.
- У reasoning-моделей часть этого бюджета может уйти на внутреннее рассуждение, поэтому видимый ответ получает заметно меньше.
- Gemini возвращает `finishReason: MAX_TOKENS`, Anthropic — `stop_reason: max_tokens`, OpenAI/Groq — `finish_reason: length`.
- Адаптеры выбрасывали эти признаки. Более того, прежний regression test прямо закреплял частичный `MAX_TOKENS` как обычный успех.
- Клиент не мог отличить цельный ответ от обрывка и честно отрисовывал всё, что получил.

## Новый контракт

1. Каждый provider adapter возвращает нормализованные `finishReason` и `truncated`.
2. Обычный законченный ответ требует ровно один запрос — speculative retry нет.
3. Явный provider truncation или объективно незакрытый Markdown запускает один recovery-проход.
4. Recovery не приклеивает продолжение к сломанной строке. Модель заново пишет **полный** ответ, получает `4000` output tokens и ограничение до 700 слов.
5. Если и второй проход оборвался, сервер отвечает `incomplete_response`; частичный психологический совет не покидает сервер как успешный результат.
6. Клиент объясняет ситуацию нормальным текстом на RU/EN/DE/UK/ES вместо внутреннего кода ошибки.

## Узкий integrity gate

Помимо provider metadata проверяются только невозможные для готового ответа состояния:

- незакрытый fenced code block;
- нечётное число парных `**`;
- пустой маркер списка или пункт вида `2. **` в конце.

Gate намеренно не пытается оценивать качество, тон или «законченность мысли» по смыслу — это дало бы ложные блокировки нормального текста.
