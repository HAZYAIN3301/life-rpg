## Фокус → сохранённая сессия → проект

Новые таймеры получают ID, время начала и владельца аккаунта. При обычной остановке
сохраняется отдельная серверная квитанция; минимум одна активная минута, максимум 24 часа
в одной квитанции. Паузы и перерывы помодоро исключаются. Это модель доверия к таймеру
клиента, а не доказательство реальной концентрации. Старое actualMin не конвертируется.

POST /api/focus/sessions: {accountId,session:{id,taskId,startedAt,endedAt,activeMs}}.
Сессия принадлежит текущему аккаунту и ссылается на его сохранённую задачу. Проверяются
origin, JSON, размер, время, идентичность аккаунта до и после чтения тела. Запись через
fsync/rename/fsync directory; успех только после неё. Повтор не добавляет строку.
Если другой таб первым остановил тот же таймер, его подтверждённая запись авторитетна;
другая taskId/startedAt не принимается как этот же результат.

Клиент хранит точный ожидающий запрос в localStorage отдельно по аккаунтам, повторяет
после входа/reload/online и по кнопке. Пока подтверждения нет, в «Сегодня» и проекте виден
статус. Отказ записи очереди оставляет остановленный таймер для повтора, не стирает его.
Чужой таймер не восстанавливается после смены аккаунта. Данные private; имён задач в
квитанции нет. Серверный focus-sessions.json закрыт для generic data и admin restore,
не импортируется переносимым архивом; удаление аккаунта удаляет его вместе с каталогом.

В проект можно внести фокус по ещё открытой задаче. Хеш источника совпадает с хешем самой
задачи: сессия, повторные сессии и последующее завершение одной задачи дают один вклад
за весь цикл группы. Это альтернативный способ внести дело, не новый источник золота.
Уже завершённая задача участвует обычным путём. Исторические task-хеши не меняются.

Новая квитанция независима от прежней записи суммарных минут задачи. Старый механизм
Store.save(actualMin) не объявляется атомарным с новой квитанцией и не переписан этим
выпуском. Завершение задачи использует существующий результат дела; отдельной квитанции
при stopFocus(false) не создаётся, чтобы не утверждать сохранение ещё не завершённого действия.

## Полученная личная награда → использование

G03, первая часть: отдельный раздел полученных наград. Состояния: получено, запланировано
на дату, использовано, отложено; доступен возврат для исправления отметки. Запланированная
на сегодня/прошедший день награда появляется одной спокойной карточкой в «Сегодня».
Без запланированной даты старые покупки не создают напоминаний.

История purchases неизменяема и остаётся у своего владельца. Метки живут отдельно в
settings.rewardLifeV1, ключ — ID личной покупки с rewardId. Мебель/косметика/gear сюда не
попадают. Запись через существующий economyCommit/CAS/WAL; при потере ответа повторяется
тот же кандидат. Поздний ответ после смены аккаунта/эпохи не применяется.
Статусы не списывают и не возвращают золото, не выполняют реальную покупку.
Интерфейс прямо разделяет игровую оплату и необходимый реальный бюджет. Реальная цена,
доступность по финансовым данным и интеграция с финансами — незавершённая часть G03/G04.

## Приёмка и границы

- HTTP: session auth/origin/account fence, отказ записи, настоящий process exit после
  rename, restart/replay, task/focus dedupe, приватность, corrupt storage.
- Чистые проверки: исключение пауз/перерывов, конфликт, local queue, reload/account fence;
  reward lifecycle не меняет покупки, владение или баланс.
- Chrome/WebKit: на движок 10 завершений дел + 2 привычки + 2 фокуса, оба проекта;
  реальный stopFocus с ускоренным временем fixture, local quota, потеря HTTP-ответа/reload;
  покупка → план → потеря ответа/повтор → Сегодня → использование → reload.
- Матрица: 120 состояний проектов + 160 состояний личных наград, 5 языков, 2 темы,
  mobile/desktop; contrast/touch, прежние keyboard/200%-text/reduced-motion проверки.
  Итог: **3245/3245**, 0 fail/skip, 56.00 с; **280 состояний**, 0 page errors,
  минимальный контраст **6.40:1**. Syntax и diff PASS. Release receipt — в CHECKPOINT после выпуска.

Доказательства: work/m07; существующий browser runner кладёт PNG и report.json в
work/m05/evidence. Реальных production-аккаунтов не меняли. Визуальные варианты матрицы
задаются fixtures, сохранение отдельно проверяется настоящими HTTP-запросами.
Оплата/Pro, Senku и полоса Claude не изменены.

## Баланс золота: воспроизводимая база

scripts/qa-gold-runway.mjs исполняет текущую itemGold из app.js и читает реальный каталог.
Семь предметов за золото стоят суммарно 1940; текущая выделенная тройка — 1080.
Без бонусов, сундуков, целей, пропусков и прочих трат: 21/66/153 золота в день дают
93/30/13 дней на все семь предметов. Это синтетические сценарии, не данные аудитории.
Уровни ограничивают доступ отдельно. Условный баланс 8000 покрывает всю коллекцию и
оставляет 6060. Значит, одних новых способов зарабатывать недостаточно: нужно проверить
желанность вещей и повторную пользу общего пространства до расширения ассортимента/цен.
