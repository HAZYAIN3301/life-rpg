# Telemetry Consent v1 — AG-51 / AG-53 / AG-54

> Невидимый фундамент. `public/telemetry-consent-v1.js` — чистая политика; эндпойнты в
> `server.js` дают ей диск и границу аккаунта. UI согласия не нарисован — это зона Codex.

## Карточки аудита

Три карточки, один корень: в продукте нет слова, которым можно отличить «это нужно, чтобы
приложение работало» от «это нужно, чтобы человек дольше сидел». Пока такого слова нет,
второе всегда прячется за первым — не по злому умыслу, а потому что прятаться больше негде.

| Карточка | Дыра | Чем закрыта |
|---|---|---|
| **AG-51** (P0) | Поведенческие эксперименты над людьми без согласия и без границ | `evaluateExperimentEligibility` требует и согласия, и `contractId` + `owner` + `reviewAt` |
| **AG-53** | Аналитика меряет вовлечение и называет это пользой | `product_improvement` и `engagement_optimization` — разные цели с разными согласиями; `NEVER_IMPLIED` фиксирует, что одна не подразумевает другую |
| **AG-54** | Нет разделения между необходимым для работы и необходимым для вовлечения | Ровно одна цель `essential`; `engagement_optimization.essential === false` проверяется тестом |

## Цели

| Цель | Необходима | По умолчанию | Хранение | Что это |
|---|---|---|---|---|
| `service_operation` | **да** | вкл | 30 дн. | Сбои, потери данных, неудавшиеся сохранения |
| `safety` | нет | вкл | 180 дн. | Признаки компульсии, ночных сессий, сожаления |
| `product_improvement` | нет | вкл | 180 дн. | Помогает ли функция довести дело до конца |
| `personalization` | нет | вкл | 365 дн. | Подстройка подсказок под привычки |
| `engagement_optimization` | нет | вкл | 90 дн. | Как сделать, чтобы человек возвращался чаще |
| `experimentation` | нет | **выкл** | 180 дн. | Проверка гипотез на живых людях |

**Позиция по умолчанию — opt-out**, и это осознанный выбор владельца продукта: цели сбора
включены сразу, человек выключает то, что не хочет. Разделение целей от этого не исчезает
— оно и есть содержание AG-53/54: цели остаются раздельными, независимо выключаемыми, с
разными сроками хранения и раздельными счётчиками в самом агрегате.

**Исключение ровно одно: `experimentation` выключена по умолчанию.** Эксперимент — это не
сбор, а изменение того, что видит конкретный человек, ради проверки гипотезы на нём.
Другой поступок — другое умолчание (AG-51). Включается одним словом (`defaultOn: true` в
таблице целей), если решишь иначе.

«Необходима» и «включено по умолчанию» — разные вещи. Необходимую цель нельзя выключить
вообще; остальные включены, но у каждой есть выключатель.

**Необходима ровно одна цель.** Это не экономия — это и есть содержание AG-54: как только
«необходимых» целей становится две, вторая немедленно начинает означать «нам это очень
нужно», и разделение исчезает. У необходимой цели обязано быть поле `whyNotOptional` —
объяснение, которое видит человек.

Необходимое **не подразумевает ничего**: `NEVER_IMPLIED.service_operation` перечисляет все
остальные цели. Право собирать сбои не даёт права собирать что-либо ещё.

## Границы

Модуль **не**: не пишет события, не ходит в сеть, не смотрит на часы, не знает про HTTP.
Он отвечает «можно или нет и почему»; собирает и хранит сервер.

## API

```js
const C = require('./public/telemetry-consent-v1.js');   // или globalThis.TelemetryConsentV1
```

### `defineTelemetryPurposes() → purposes[]`

Полная таксономия для показа человеку: `id`, `essential`, `retentionDays`, `label`,
`description`, `whyNotOptional`.

### `normalizeConsent(input) → consent`

```js
{ version: 1, purposes: { <id>: boolean }, decidedAt, source, history: [{ at, purpose, granted, source }] }
```

Решением считается только настоящий `boolean`. `'да'`, `1`, `'true'` решением не
являются — за них отвечает умолчание, а не догадка о намерении.

Состояние необходимой цели **не читается из файла** вообще: испорченный или подделанный
файл не должен уметь её выключить.

**Отзыв переживает порчу файла.** Если поле с целями нечитаемо, но в `history` есть запись
об отзыве — цель остаётся выключенной. При opt-out это единственное, что мешает «починке
умолчанием» молча вернуть сбор, который человек выключил.

### `applyConsentDecision(consent, decision) → { ok, reason, consent, changed[] }`

`decision = { at, source, purposes: { <id>: boolean } }`. Вход не мутируется.

Отзыв разрешён всегда и действует сразу. Выдача требует `at` и `source`: согласие без
«когда и где» невозможно ни показать, ни оспорить, а значит его как бы и нет.

Необходимая цель не предлагается как выбор — попытка её выставить возвращает
`essential_not_a_choice:<id>`, а не молчаливое согласие. Молча «согласиться» с попыткой
её выключить значило бы соврать человеку о том, что он только что сделал.

Причины отказа: `invalid_decision`, `invalid_decision_time`, `invalid_decision_source`,
`unknown_purpose:<id>`, `invalid_value:<id>`, `essential_not_a_choice:<id>`.

### `evaluateEventPermission(consent, event) → verdict`

`event = { name, purpose, at?, props? }` → `{ allowed, reason, purpose, essential, retentionDays, event }`.

- **Цель обязательна и всегда одна.** Событие без цели — не «наверное служебное», оно
  неизвестно чьё (`purpose_required`). Событие, объявившее две цели, отвергается
  (`single_purpose_required`): это и есть способ, которым оптимизация вовлечения ездит на
  согласии, данном для чего-то другого.
- **`props` принимает только булевы и конечные числа.** Свободный текст —
  единственный способ протащить в телеметрию содержимое жизни человека: название задачи,
  имя, ссылку. Поэтому строк здесь нет вообще, а не «строки, которые мы почистили»
  (`free_text_not_allowed`). Отклонённый текст не попадает и в сам вердикт.
- `name` санитизируется той же маской `[^\w:.-]`, что и раньше на сервере.

### `filterEventBatch(consent, events) → { accepted, rejected }`

Отклонённые возвращаются с причиной: телеметрия, которая молча теряет часть событий, врёт
своим же отчётам.

### `evaluateExperimentEligibility(consent, assignment) → { eligible, reason, ... }`

`assignment = { experimentId, contractId, owner, reviewAt, purpose }`.

Эксперимент над человеком требует двух вещей сразу, и ни одна не заменяет другую:
**согласия человека** и **границ, объявленных заранее**.

`contractId` — ссылка на контракт из [`gamification-governance-v1`](GAMIFICATION-GOVERNANCE-V1.md):
там живут pre-mortem, метрики вреда, пороги остановки и план отката. Эксперимент без
контракта не «недооформлен» — у него нет выключателя, и это отказ.

Отказы: `experiment_consent_missing`, `no_governance_contract`, `no_owner`,
`no_review_date`, `purpose_consent_missing`, `invalid_experiment`, `unknown_purpose`.

Согласие «ставьте на мне опыты» **не** означает согласия «оптимизируйте моё вовлечение»:
эксперимент с `purpose: 'engagement_optimization'` требует и того согласия тоже.

### `describeConsentForHuman(consent) → string`

Детерминированный текст: что собирается, зачем, насколько долго хранится, когда человек
это решил, и прямым текстом — что согласие на пользу не означает согласия на вовлечение.

Четыре состояния, и разница между ними — главное, что делает opt-out честным:
«всегда включено» (необходимое), «включено вами», **«включено по умолчанию — можно
выключить»**, «выключено вами». Без третьей строки opt-out и был бы тем самым нечитаемым
соглашением.

## Эндпойнты

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/telemetry/consent` | `{ consent, purposes, essential, human }` |
| `PUT` | `/api/telemetry/consent` | `{ source, purposes }` → `{ ok, changed, consent, purposes, human }` |
| `POST` | `/api/analytics` | как раньше, но через гейт согласия |

Хранение: `users/<uid>/telemetry-consent.json`. Нечитаемое согласие читается как
отсутствие согласия — единственное безопасное толкование.

`source` из тела принимает только `settings` и `onboarding`. `import` и `default`
подписать решение не могут: так согласие не принимают.

### Согласие намеренно НЕ входит в переносимый архив

`ACCOUNT_PORTABLE_FILES` управляет и экспортом, и импортом одним списком. Согласие — это
решение, которое принимают, а не файл, который восстанавливают: импорт архива не имеет
права заново включить сбор, который человек с тех пор выключил. Своё согласие целиком
человек читает через `GET /api/telemetry/consent`. Удаление аккаунта уносит его вместе с
каталогом пользователя.

## Что меняется для существующего кода

**Ничего не ломается и сбор не прерывается.** `POST /api/analytics` теперь пропускает
событие только при включённой цели, но цели сбора включены по умолчанию — существующие
вызовы `track()` из `app.js` работают ровно как раньше.

Такое немаркированное событие считается `product_improvement`, а **не**
`service_operation`: неизвестно чьё событие не имеет права ездить на служебной
необходимости. Практическая разница — у него свой выключатель и свой срок хранения (180
дней вместо 30).

Отказ, когда человек цель выключил, — это `200 { ok: true, recorded: false, reason:
'consent_missing' }`, а не ошибка. `track()` ответ не читает, так что и в этом случае
ничего не ломается.

В агрегат добавлен разрез по целям — `data[day].purposes[<id>]`. Разделение видно в самих
данных, а не только в коде: отчёт, в котором нельзя отделить вовлечение от пользы,
воспроизведёт AG-53 через месяц.

### Про юридическую сторону — коротко и честно

Opt-out для неслужебной аналитики в ЕС/Германии под DSGVO не считается действительным
согласием, и вписывание этого в длинное пользовательское соглашение положения не меняет:
согласие должно быть отдельным и активным. Экспозиция здесь при этом маленькая — эндпойнт
хранит только имена событий и счётчики, без содержимого.

Вся механика для перехода на opt-in уже стоит и оттестирована: достаточно поставить
`defaultOn: false` у нужных целей в таблице `PURPOSE_LIST` — сервер, хранение и выключатель
менять не придётся.

## Тесты

```bash
node --test scripts/telemetry-consent-v1.test.js scripts/telemetry-consent-server-v1.test.js
```

- `scripts/telemetry-consent-v1.test.js` — 19 тестов: ровно одна необходимая цель,
  вовлечение не бывает необходимым, умолчание «нет», подделанный файл ничего не включает,
  необходимое не выбирают, событие без цели, две цели у одного события, свободный текст,
  границы эксперимента, связь с governance-контрактом, человекочитаемое описание,
  отсутствие мутации входа и сети.
- `scripts/telemetry-consent-server-v1.test.js` — 10 тестов: без согласия сбор не
  происходит и приложение не ломается, необходимое не даёт права на остальное, польза не
  включает вовлечение, отзыв действует немедленно, свободный текст не оседает нигде в
  data-каталоге, чужое согласие недосягаемо, повреждённый файл, валидация PUT, удаление
  аккаунта, отсутствие в архиве.

## Integration contract для Codex

- Модуль в HTML **не подключён**, экран согласия не нарисован.
- Экран настроек строится из `GET /api/telemetry/consent`: `purposes` даёт метки,
  описания, сроки хранения и `defaultOn`, `essential` — что показать как «всегда включено»
  вместе с `whyNotOptional`, `human` — готовый текст, если он нужен целиком.
- Экран обязан показывать, что цель включена по умолчанию, и давать выключатель рядом.
  Именно это отличает opt-out от нечитаемого соглашения — и это единственная часть,
  которая сейчас держится на Codex, а не на коде.
- Когда `track()` начнёт объявлять цель, менять сервер не потребуется — достаточно
  добавить `purpose` в тело. Умолчание `product_improvement` останется для того, что
  не размечено.
- Любой A/B над механикой обязан пройти `evaluateExperimentEligibility` **до** назначения
  варианта, а не после.
