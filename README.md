актуальными без проверки. Канонический порядок чтения:

1. [`START-HERE.md`](./START-HERE.md) — холодный старт и актуальный release-handoff.
2. [`AGENTS-PROTOCOL.md`](./AGENTS-PROTOCOL.md) — обязательный безопасный процесс,
   совместная работа, тесты, commit, push и deploy.
3. Верх [`DEVLOG.md`](./DEVLOG.md) — что фактически выпущено.
4. Верх [`BACKLOG.md`](./BACKLOG.md) — что действительно осталось.
5. Профильный spec/QA-файл функции, которую меняешь. Для текущего слоя Actionable

старые handoff-файлы — исторические снимки, если в их шапке не сказано обратное.

## Как запустить

**Просто:** двойной клик по `Запустить.command` (откроет браузер и поднимет сервер).

**Из терминала:**

```sh
cd "life-rpg"
npm start          # → http://127.0.0.1:4317
```

Зависимостей нет — `npm install` не нужен. Достаточно установленного Node.js.

## С телефона/планшета

Production работает как PWA, а локальный сервер можно открыть в той же Wi-Fi сети:

```sh
npm run lan        # сервер слушает всю сеть (HOST=0.0.0.0)
```

затем на телефоне открой `http://<IP-мака>:4317`. Нативные iOS Screen Time / Family
Controls возможности требуют отдельного Apple entitlement; точная карта ограничений —
[`APPLE-DEVELOPER-FUTURE-HANDOFF.md`](./APPLE-DEVELOPER-FUTURE-HANDOFF.md).

## Данные

- `data/users/<id>/settings.json` — настройки, сферы и часть связанных графов.
- `data/users/<id>/tasks.json` — задачи; защищённые записи settings+tasks проходят
  через exact-CAS/WAL-контракт.
- `data/users/<id>/*.json` — остальные домены аккаунта, включая цели, дни, профиль и
  отдельные состояния функций.

На Railway `DATA_DIR` находится на персистентном томе. Экспорт и удаление данных доступны
через продуктовые маршруты; ручное редактирование живых файлов может нарушить ревизии и
графовые инварианты.

## Архитектура

- `server.js` — Node stdlib, отдаёт фронтенд + auth/API и атомарно пишет пользовательские JSON.
- `public/` — фронтенд на чистом JS, без сборки и без библиотек (графики — рисованный SVG).

Runtime остаётся zero-dependency: Node stdlib + vanilla JS, без frontend build-step.

## Сброс пароля письмом

Не обязателен: без переменных ниже кнопка «Прислать письмо» не показывается, а
восстановление продолжает работать по коду, который выдают при регистрации.

Чтобы включить — завести в Railway (Variables):

| Переменная | Что это |
|---|---|
| `RESEND_API_KEY` | ключ [Resend](https://resend.com) — 3000 писем/мес бесплатно |
| `RESET_MAIL_FROM` | отправитель, например `Satoru <noreply@твой-домен>` |
| `PUBLIC_BASE_URL` | адрес прода, чтобы ссылка в письме вела куда надо |

`RESET_MAIL_FROM` требует домена, подтверждённого в Resend. Без своего домена
работает дефолтный `onboarding@resend.dev`, но такие письма чаще уходят в спам —
для боевого запуска домен лучше подтвердить.

Ссылка одноразовая и живёт час; повторное письмо на тот же адрес — не чаще
раза в две минуты.
