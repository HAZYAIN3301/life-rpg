# Skill-tree v2 — план развития (spec для ultracode)

> Превратить древо навыков из «ламборгини в пыли» в живой движок прогрессии. Self-contained, не требует активного участия Альберта — все дизайн-решения приняты ниже, он корректирует постфактум. Стиль работы — `feedback`-памятки: ship по фазам, DEVLOG на каждую фазу.

## Диагноз: почему древо не используется (факты из кода)

- **Один-единственный перк** — `perkXpPct` (`skillPerkBonus`, app.js:1790; подключён к XP на 1876). Это всё, что даёт древо. Перк циркулярный и скучный: +%XP → больше уровней → больше очков → +%XP. Ничего осязаемого.
- **Генерические деревья** — `defaultTreeForSkill` (app.js:2345) выдаёт ОДИНАКОВЫЕ 5 абстрактных узлов (Старт/Регулярность/Глубина/Широта/Мастерство) для ЛЮБОЙ сферы. Ноль флавора, ноль смысла.
- **Чистый холст** — прокачка спрятана за ручным редактором (`treeNodePanel`, drag, add/del). Никто не строит дерево руками → оно пустует.
- **Изолировано** — древо не связано с питомцами, спутником, экономикой, энергией, наградами, рейдами. Качать незачем.
- **Очки = уровень сферы** (`treePointsEarned = skillLevelOf`) — механика очков есть и работает, её сохраняем.

## ВИ ́дение v2

Каждое дерево сферы — осмысленная ветка прокачки, которая (1) даёт **разнообразные осязаемые перки**, (2) приходит **предсобранной под тему сферы** (zero-config), (3) ведёт к **капстоуну** (сигнатурный финальный узел), (4) **связана** с питомцами/спутником/экономикой/энергией.

---

## Фаза 1 — Движок перков (разнообразие вместо одного %XP)

**Цель:** узел даёт не только +%XP, а любой из набора осязаемых эффектов.

Схема узла: добавить `perks: [{kind, val}]` (старое `perkXpPct:N` мигрируется в `[{kind:'xpPct', val:N}]`).

`PERK_KINDS` реестр (kind → {label, icon, scope, apply}). Набор (все хуки уже существуют в коде — переиспользуем):

| kind | эффект | хук в коде |
|---|---|---|
| `xpPct` | +N% XP в этой сфере | уже на app.js:1876 |
| `goldPct` | +N% золота с квестов сферы | рядом с `goldFor` (1881, есть `gearBonus().goldPct`) |
| `lootLuck` | +N% к буст-шансу сундука | `lootBoostPct()` (есть на 1876) |
| `energyBack` | квест в сфере возвращает +N энергии | система энергии (есть «Энергия 100/100») |
| `streakShield` | +N спасений стрика | щадящий стрик (есть) |
| `petBoost` | питомец сферы сытнее/быстрее растёт | `petStats` (app.js:4123) |
| `bond` | +N к связи со спутником при делах в сфере | companion bond |
| `title` | разблокирует звание/косметику | система рангов/наград |

Агрегаторы: `skillPerks(id)` (по сфере), `globalPerks()` (сумма по всем). Каждый kind хукается в свою систему (один helper на kind). Балансные капы — см. ниже.

**Миграция:** при загрузке — старые узлы с `perkXpPct` → `perks:[{kind:'xpPct',val}]`. Обратная совместимость с сохранёнными деревьями.

Фаза 1 = ship: перки считаются и применяются. UI пока старый.

## Фаза 2 — Курируемые шаблоны деревьев по архетипу сферы

**Цель:** убрать «чистый холст» — дерево приходит тематическим и осмысленным.

`TREE_TEMPLATES` по архетипу. Архетип определяем как в питомцах (`PET_TRAITS`-регексы по имени/подсферам): физо/учёба/работа/творчество/соц/здоровье/быт/generic.

Каждый шаблон = 7–10 узлов, ветвистая структура, разные `kind` перков, **капстоун** (дорогой финальный узел с сигнатурным перком: уникальное звание + сильный пассив). Примеры тематики:
- **Физо:** Разминка(energyBack) → Выносливость(xpPct) / Сила(goldPct) → Дисциплина(streakShield) → капстоун «Атлет» (title + petBoost).
- **Учёба:** Фокус → Память → Глубина(xpPct) / Широта(lootLuck) → капстоун «Эрудит».
- **Творчество, Работа, Соц, Здоровье, Быт** — аналогично, свой флавор + перки.

`defaultTreeForSkill` → выбирает шаблон по архетипу. **Миграция для существующих юзеров:** если дерево не трогали (все узлы дефолтные/locked) — заменить на шаблон; если кастомил (есть unlocked/изменённые) — НЕ трогать, предложить кнопкой «обновить до шаблона». Альберт не теряет правки.

Фаза 2 = ship: новые сферы и нетронутые старые получают тематические деревья.

## Фаза 3 — UX-редизайн древа (из графа в RPG-ветку)

**Цель:** чтобы хотелось качать.

- **Тиры/ряды** с визуальной иерархией; линии-ветви читаемые; состояния узла: unlocked / available (подсвечен, «можно взять») / locked (затемнён, виден замок+требования).
- **«Рекомендую дальше»** — подсветка следующего доступного узла.
- **Капстоун** — визуально особый (крупнее, свечение, корона).
- **Панель активных пассивок** сверху: «Твои бонусы в этой сфере: +15% XP, +1 спасение стрика…» — чтобы эффект был виден.
- Экономика очков ясная: заработано/потрачено/доступно + откуда очки.
- Редактор сохраняем для power-режима, но дефолт — zero-config и наглядный.

Фаза 3 = ship: древо выглядит и ощущается как настоящая прокачка.

## Фаза 4 — Интеграция + баланс + доки

- **Связки:** спутник упоминает свежевзятый перк; питомец сферы отражает `petBoost`; звания из `title`-узлов видны в профиле/гардеробе.
- **Баланс-пасс:** капы (общий `xpPct` ≤ ~40%, `goldPct` ≤ ~30%, и т.д.), проверка что дерево не максится слишком рано/поздно (очки = ур. сферы; полное дерево ~ к ур. 12–18). Анти-эксплойт.
- **Тесты** в превью по всем фазам, **DEVLOG** на каждую, push.

---

## Баланс (решения приняты, корректируются позже)

- Очки = уровень сферы (как сейчас). Полное дерево стоит ~суммарно столько, чтобы закрываться к ур.~15.
- Капы суммарных пассивок, чтобы не сломать XP-экономику и анти-накрутку лидерборда (серверная валидация XP уже есть — проверить, что перки не дают серверного рассинхрона).
- Перки — «приятные», не обязательные: игра проходима без оптимальной прокачки.

## Приёмка

- [ ] ≥6 типов перков, каждый реально влияет на свою систему (проверить эффект в превью).
- [ ] Каждая сфера приходит с тематическим деревом + капстоуном; кастомные деревья не затёрты.
- [ ] Древо читаемо: состояния узлов, рекомендованный следующий, панель активных пассивок.
- [ ] Капы соблюдены; XP-экономика и серверная валидация не сломаны.
- [ ] DEVLOG на каждую фазу; миграция безопасна (старые сохранения грузятся).
