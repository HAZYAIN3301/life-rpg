# Actionable Gamification v215 — честная игровая петля

Дата: 2026-09-01
Статус: release train; runtime и целостность данных принадлежат Codex, независимые foundations переданы Claude Code.

## Зачем этот релиз

Satoru уже использовал уровни, XP, золото, серии и награды, но часть механик была только тематической оболочкой. Некоторые подписи обещали несуществующий эффект (`Hype`), детерминированный бонус назывался «удачей», а Control и старая «Клятва» опирались на угрозу потери ресурса. Это противоречило и реальному поведению продукта, и главному выводу из *Actionable Gamification*: механика должна вести к желаемому действию, а не подменять его очками или тревогой.

v215 делает первый системный срез:

- правила, показанные человеку, совпадают с кодом;
- решение можно пересмотреть или снять без штрафа;
- молчание не считается поражением;
- история остаётся для калибровки, но не превращается в долг;
- связанные `settings + tasks` сохраняются как одна проверяемая транзакция.

## Как применены восемь Core Drives

| Core Drive | Что делает v215 | Чего намеренно нет |
|---|---|---|
| 1. Meaning | обязательство содержит собственный названный выигрыш человека (`win`) | универсальной морали «так правильно» |
| 2. Accomplishment | одна честная шкала сложности: `1 / 1.5 / 1.75`; завершение и граница имеют явный исход | скрытого множителя и обещаний Hype |
| 3. Empowerment | `take / revise / release / reopen`; Control предлагает уменьшить, перенести или отпустить | необратимой «Клятвы» |
| 4. Ownership | история решения сохраняется и принадлежит аккаунту; legacy-данные мигрируют идемпотентно | ставки золотом за право изменить собственный план |
| 5. Social Influence | в этом срезе не расширяется; племя и сравнение не используются как давление | публичного стыда и рейтинга дисциплины |
| 6. Scarcity | не используется для принуждения; ограничение числа активных обязательств защищает внимание | искусственного дефицита и платного преимущества |
| 7. Unpredictability | дневная награда остаётся раскрытым честным розыгрышем; бонус золота назван детерминированно | ложной «удачи», near-miss и подкрутки |
| 8. Loss & Avoidance | используется только как диагностический анти-паттерн: старые списания исключаются из spendable gold | потери XP, золота, энергии или серии за пересмотр/пропуск |

## Код релиза

- `public/commitment-v1.js` — чистая модель обратимого решения.
- `public/commitment-store-v1.js` — строгая проверка графа `commitmentsV1 ↔ tasks`.
- `public/commitment-journal-v1.js` — чистый allowlisted write-ahead journal: обязательная пара `settings/tasks` и опциональный полный граф импорта.
- `public/gamification-integrity-v1.js` — миграции `lootLuck → dailyRewardGoldPct`, legacy Oath и synthetic purchases.
- `public/app.js` — видимые действия на квесте, Control review, фиксированная сложность и честные тексты.
- `server.js` — optimistic concurrency и durable pair commit для `settings + tasks`.

## Инварианты выпуска

1. Активный `quest:*` commitment всегда имеет ровно одну связанную задачу.
2. Задача не может ссылаться на отсутствующий commitment.
3. Изменение пары требует точный server-confirmed `base`; stale вкладка получает `409`.
4. Смерть процесса между файлами восстанавливается через journal: `prepared` откатывается, `committed` докатывается; старые двухфайловые журналы остаются совместимыми.
5. Legacy одиночная запись разрешена только до появления защищённого графа.
6. Ошибка сохранения не оставляет выполненный квест, потерянный таймер или ложный success-toast.
7. Ни одна операция CommitmentV1 не начисляет и не отнимает игровые ресурсы.
8. ИИ-импорт сфер, уровней, целей и первых квестов использует один exact CAS-base и один WAL для `settings/tasks/goals/goal-groups/skilltree`; частичная версия графа не публикуется.

## Параллельная ветка Claude Code

Claude Code получает только чистые foundations, которые не пересекаются с runtime v215:

- AG-02/05/07/56 — governance policy;
- AG-09/11/12/32 — first-value orchestration;
- AG-35 — explainable AI-memory policy;
- AG-52 — telemetry consent.

Полный контракт ownership и приёмки находится в `ACTIONABLE-GAMIFICATION-CLAUDE-HANDOFF.md`. Интеграция делается отдельным review после v215, без прямого merge `app.js` или release-файлов.
