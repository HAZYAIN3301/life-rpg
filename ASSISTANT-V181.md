# Assistant v181 — безопасный исполнитель и голосовой вход

## Результат

Ассистент больше не ограничен советом «сделай это вручную». Он умеет предложить конкретное изменение принадлежащего человеку объекта, показать точный preview и выполнить его только после отдельного нажатия человека. При этом необратимых, административных и межаккаунтных команд в его языке нет.

## Контур безопасности

```text
ответ модели
  → AssistantActionsV1: первый ACTIONS-блок, максимум 5 строк
  → whitelist вида действия
  → точный targetId из объектов текущего аккаунта
  → видимые выбранные карточки
  → отдельное подтверждение человеком
  → повторная проверка targetId по свежему State
  → awaitable commit / rollback / Retry
```

Модель не является границей доверия. Системный prompt помогает ей сформировать хороший ответ, но право на действие задают `public/assistant-actions-v1.js` и исполнитель в `public/app.js`.

### Разрешено

- создать квест, привычку или цель;
- поставить цель на паузу, возобновить или архивировать;
- перенести или завершить собственный квест;
- поставить собственную привычку на паузу или возобновить.

### Невозможно через ассистента

- удалить/уничтожить/сбросить данные;
- удалить аккаунт или пользователя;
- менять пароль, ключи, Pro, admin-права, публикацию или privacy;
- адресовать чужой объект или выбрать объект по расплывчатому текстовому фильтру;
- выполнить второй ACTIONS-блок из процитированного или внедрённого текста;
- применить карточку без отдельного нажатия человека.

Отказ показывается явно. Ошибка записи не превращается в success: исходное состояние сохраняется, а карточка остаётся доступной для Retry.

## Конкретный контекст вместо общего совета

В каждый запрос попадают релевантные текущему вопросу объекты Satoru:

- цели с устойчивыми id, статусом, инициативой, parentId и deadline;
- квесты с id, датой и completion-state;
- привычки с id и состоянием;
- текущее состояние и недельный контекст.

Локальные файлы приложение само не читает. Человек может явно выбрать один `TXT`, `MD`, `JSON` или `CSV` до 20 КБ. Файл хранится только в памяти текущей вкладки, виден как chip, удаляется отдельной кнопкой и передаётся модели как недоверенный справочный материал. Если файл не выбран, ассистент обязан честно сказать, что плана не видит, вместо выдуманного «сними видео».

Серверный лимит `system` поднят с 12 000 до 48 000 символов. Старый лимит обрезал живой контекст после длинного product manual и был непосредственной причиной общих ответов.

## Голосовой вызов

- Включается человеком внутри диалога и действует только для текущей вкладки.
- Распознаёт `Сатору…` / `Satoru…` только в начале фразы (допустимы `Эй/Hey/OK`).
- Команда открывает ассистента и заполняет **черновик**. Она ничего не отправляет и не применяет сама.
- Микрофон останавливается, когда вкладка скрыта, и возобновляется после возврата, если режим всё ещё включён.
- Отказ браузера в микрофоне показывается как видимое состояние.

Это честный web-контракт, не системная Siri: закрытая вкладка/PWA не может постоянно слушать wake word. Фоновый системный вызов требует отдельного нативного iOS/Android/desktop companion.

## UI и доступность

- Статические `…` заменены на `role=status`: «Тень формулирует ответ» + три движущиеся точки.
- При `prefers-reduced-motion` точки статичны, переходы диалога отключены.
- Диалог имеет label/description, `aria-modal`, inert-фон, Escape, backdrop-close, Tab trap и возврат фокуса.
- На mobile/coarse все контролы не меньше 42 px, поле ввода не меньше 16 px.
- Возврат из mobile More идёт на постоянную кнопку More, даже когда временный opener уже удалён.
- Новый copy и no-key state закрыты RU/EN/DE/UK/ES.
