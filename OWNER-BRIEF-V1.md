# Сводка для владельца — v1

> 20.10.2026, Claude. Запрос владельца: в утреннем брифинге Jarvis (репозиторий `HAZYAIN3301/jarvis`,
> `night/morning.mjs`) видеть Satoru — новых пользователей, подписки, отзывы и срочные баги.

## Контракт

`GET /api/owner/brief`, заголовок `Authorization: Bearer <токен>`.

```json
{
  "v": 1,
  "at": "2026-10-21T07:30:00.000Z",
  "users": { "total": 132, "new24h": 3, "new7d": 11 },
  "plans": { "pro": 5, "trial": 2 },
  "feedback": { "day": { "bug": 2, "idea": 1, "praise": 0, "other": 0 }, "bugs7d": 4 }
}
```

- **Только числа.** Ни текстов отзывов, ни id, ни почт, ни имён: сводка уходит в Telegram, а там
  нет сквозного шифрования. Тест ищет в ответе текст отзыва и почты.
- `plans` — по существующему `entitlement()`; админ — создатель, в тарифах не считается.
- `feedback.day` — за последние сутки по видам из `/api/feedback`; неизвестный вид — `other`.
- Активных за сутки нет: у аккаунта нет надёжной отметки последнего входа, выдумывать её не стали.

## Доступ

- На Railway хранится **только SHA-256 токена** — переменная `OWNER_BRIEF_TOKEN_SHA256`. Не задана —
  маршрута нет (404). Неверный токен — 401. Кука админа — не токен.
- Сам токен лежит в связке ключей Jarvis (`jarvis-satoru-brief`). Создаётся там же одной командой,
  она печатает хэш для Railway (`jarvis/night/README.md`).
- Модуль — `server-owner-brief-v1.js`, тесты — `scripts/owner-brief-v1.test.js`: сводка на
  синтетических данных, токен, маршрут на настоящем сервере с временным DATA_DIR.
