# Actionable Foundations UI v216

Дата: 2026-09-06  
Статус: реализовано, ожидает release-проверки

## Результат

Четыре основания из аудита Actionable Gamification доведены до продуктового шва без
дублирования их решений в `app.js`:

1. `FirstValueV1` ведёт нового человека к одному доказанному результату, а не к
   экскурсии по интерфейсу.
2. `AiMemoryPolicyV1` делает память Тени видимой, объяснимой, исправляемой,
   отключаемой, удаляемой и экспортируемой.
3. `TelemetryConsentV1` разделяет сбор по назначению и показывает человеку не
   бинарный переключатель, а происхождение текущего состояния.
4. `GamificationGovernanceV1` остаётся внутренним контрактом команды. Пользовательского
   экрана и browser-подключения у него намеренно нет.

## Где это видно

### Первая ценность

Карточка появляется на экране «Сегодня» только у новых регистраций. Старые аккаунты
автоматически в эксперимент не включаются. Человек выбирает один из трёх маршрутов:
сделать готовый шаг, уточнить следующий шаг или начать ограниченное восстановление.

Главное действие всегда одно. Остальная поддержка вторична. Успех показывается только
после подтверждённой записи предметного результата:

- завершён квест;
- сохранён следующий шаг цели;
- сохранён настоящий план из онбординга;
- сохранена граница восстановления.

Создание квеста само по себе не считается победой. Оно лишь подготавливает ссылку на
действие. Это одинаково работает из «Сегодня» и календаря. Если сохранение пути или
события не удалось, интерфейс не переходит вперёд и не празднует результат.

### Память ассистента

Экран: `Настройки → Связи → Что Тень помнит`.

Каждая структурная запись показывает:

- сам факт;
- откуда он появился (`origin`);
- где используется (`usage`);
- действия «исправить», «не использовать / вернуть» и «удалить»;
- экспорт всей памяти отдельным архивом.

Снятые записи остаются видимыми и восстанавливаемыми. Если файл читается лишь частично,
все мутации блокируются, а человек получает прямое объяснение вместо ложного пустого
состояния. Старая свободная карточка профиля остаётся отдельной.

### Телеметрия

Экран: `Настройки → Данные и приватность → Диагностика и улучшение`.

У каждой цели сбора видны описание и реальный срок хранения. Интерфейс различает:

- «Всегда включено» — только служебная диагностика, без переключателя;
- «Включено по умолчанию — можно выключить»;
- «Включено вами»;
- «Выключено вами».

Эксперименты выключены по умолчанию. Сервер принимает решение только с источником
`settings` или `onboarding`; импорт и неизвестный источник отвергаются, а не маскируются
под решение в настройках. Аналитика хранится раздельно по назначению и удаляется по
сроку конкретной цели: 30 / 90 / 180 / 365 дней.

## Надёжность данных

- Structured memory и старая карточка лежат в одном `profile.json`, но generic
  `PUT /api/data/profile` перечитывает актуальные structured entries непосредственно
  перед атомарной записью. Устаревшая открытая форма не воскресит уже удалённую память.
- Повреждённая structured memory даёт `422` и не перезаписывается пустым массивом.
- Некорректно закодированный id памяти даёт `400`, а не роняет процесс.
- Экспорт памяти не смешан с переносимым архивом аккаунта и не меняет согласие на сбор.
- App shell и Service Worker используют один cache release `satoru-v243`.

## Архитектурная граница

Чистые модули являются единственным источником решений. UI-адаптеры только:

- получают view/state;
- рендерят его;
- передают явное действие человека;
- сохраняют получившийся JSON существующим durable-путём.

`public/gamification-governance-v1.js` поставляется и тестируется для команды, но не
загружается в браузер. Перед будущим A/B назначение обязано пройти
`TelemetryConsentV1.evaluateExperimentEligibility` и иметь governance-контракт с
владельцем, сроком пересмотра и выключателем.

## Отложено осознанно

1. `FirstValueV1` не умеет заменить устаревший `primaryAction`. UI безопасно отправляет
   человека к выбору актуального шага, но для бесшовной замены нужен новый engine event.
2. Редактор памяти готов, однако автоматические producer-ы структурных воспоминаний
   должны строиться отдельно и проходить `AiMemoryPolicyV1`, особенно для inferred и
   sensitive данных.
3. Для пользователей в Германии/ЕС opt-out необязательной аналитики требует отдельного
   юридического решения. Текущий экран честно показывает контракт движка, но это не
   заменяет проверку правового основания и, вероятно, переход на active opt-in.
