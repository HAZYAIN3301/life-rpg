# Phone workflow — v318, 02.10.2026

Задача: продолжение видео владельца 01.10 после v317. База origin/master 07f24e29.

## Реализовано

- Функциональные иконки: единая округлая монохромная SVG-система для сложности ×3,
  границы, фокуса, ядра дня, удаления, календаря/дома, задач, карточек и ввода.
  Неизвестная картинка задачи получает осмысленный знак задачи. Известные UI-переводы
  и тосты очищаются от эмодзи; пользовательские названия не переписываются.
  Игровые иллюстрации и наградные предметы остаются контентом; это не замена всей графики.
- Заметки: одна колонка, тихие разделители, ввод и сохранение впереди, микрофон/видео
  вторичны; один счётчик. Проверены 28 заметок, пустой экран и обе темы.
- Неделя на телефоне: семь групп дел вместо только выбранного дня. Намерение вынесено
  над делами. Сохранение намерения ожидает подтверждение сервера.
- «Заход», итог и план недели открывают существующий ИИ-диалог с выбранным делом/неделей.
  Причины невыполнения уточняются, не выдумываются. Существующие ключи и подтверждение
  действий сохранены. Длинная цель-идентичность исключена из инструкций вечерней речи.
- Постоянное расписание: текст → ИИ-разбор → редактируемые дни/интервалы → сохранение.
  Можно вводить вручную. Повторяется еженедельно; исключения по датам пока не поддержаны.
  Поле settings.weeklyRoutineV1 = {text, blocks:[{day,start,end,title}], from,to}.
  day: 0=воскресенье. До 70 интервалов, 6000 символов текста; ночные интервалы не принимаются.
- Подбор свободного времени — отдельный чистый WeekPlannerV1. Только незавершённые дела
  выбранной недели без времени; активные обязательства исключаются. Длительность нужна
  явно, без догадок. Назначенные дела и регулярные интервалы заняты; неизвестная длительность
  назначенного дела блокирует остаток дня. Время в прошлом исключено. Предпросмотр перед Apply.
  Переносы проходят штатным writer, без XP/золота. Изменившийся план отвергает старый preview.
- Сохранение расписания использует settings CAS/WAL через economyCommit. После потерянного
  ответа повтор использует тот же запрос. Частичная серия переносов не объявляется успехом;
  уже перенесённые дела не предлагаются заново после reload.

## Native — отдельная сборка обязательна

В satoru-ios (локальный commit 452a68b) подготовлены AVAudioSession playback после диктовки, нативный Speech bridge
и локальный Vision OCR. Web включает их только при capability новой оболочки.
Текущий TestFlight build 9 этих возможностей не имеет. Публикация web не обновляет бинарник.

Фото расписания: JPEG/PNG/WebP до 12 MiB, нормализация до 1800px; распознавание на устройстве.
Только отдельное нажатие «Разобрать расписание» отправляет отредактированный текст в ИИ.
Обычный браузер/старая оболочка предлагают текст и ручной ввод, без неработающей фотокнопки.
Speech может использовать серверы Apple; добавлены системное описание и переводы 5 языков.
Перед native-релизом пересмотреть privacy declaration для диктовки.
