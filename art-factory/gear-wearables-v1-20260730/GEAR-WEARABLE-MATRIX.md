# GEAR → wearable matrix v1

## Решение по контракту

Каждый объект `GEAR` производит **два разных артефакта**:

1. `inventoryIcon` — самостоятельный квадратный предмет для арсенала,
   магазина, лута и карточек. Он не содержит рамку редкости, цену, цифры,
   персонажа или фон: это добавляет UI.
2. `avatarLayers` — отдельный character-specific bundle на общем холсте
   1024×1536. Traveller и Scholar не используют один и тот же PNG:
   совпадает дизайн предмета, но различаются якоря, масштаб, окклюзия и
   иногда набор подслоёв.

Все avatar PNG композитятся в `(0,0)`. ИИ отвечает только за материал,
бумажную фактуру и свет. Силуэт, якоря, маски, нормализация и порядок
композита детерминированы.

### Почему стат-GEAR и wearable не надо снова разделять

Старый `PETS-EQUIPMENT-PLAN.md` сознательно разводил стат-снаряжение и
косметические наряды. Для новой системы это остаётся верным на уровне
движка, но один `GEAR.id` может иметь визуальную проекцию:

- бонусы продолжают жить в существующем `GEAR`;
- `inventoryIcon` и `avatarLayers` являются арт-метаданными;
- отсутствие готового avatar bundle не блокирует владение и бонус;
- runtime не должен подменять emoji до прохождения арт-QA.

## Слоты и типовые bundles

| GEAR slot | Inventory | Avatar projection | Типичный порядок |
|---|---|---|---|
| `weapon` | полный предмет, диагональная hero-поза | отдельный static carry bundle и/или action grip bundle | `weapon-back → avatar → grip/weapon-front` |
| `armor` | узнаваемый торс/силуэт комплекта | character-specific замена outfit, иногда с rear/front частями | `armor-rear → body-safe → armor-main → body-visible → accessories` |
| `amulet` | крупный кулон с короткой цепью | neck/chest overlay с конфликтами scarf/current amulet | `outfit → amulet-chain-back → body/face → amulet-front` |

## Приоритет производства

1. Закрыть `weapon-grip-v1`: новые forearm+hand pose layers для Traveller и
   Scholar, затем повторно собрать `w1`.
2. Сделать `m1`: он проверит neck-anchor, scarf/amulet conflicts и самый
   дешёвый reusable pipeline.
3. Сделать `a1`: первый честный outfit-replacement, не геометрический badge.
4. После трёх пилотов масштабировать семейства: `w2b → w2 → w3 → w4`,
   `m2b → m2 → m3 → m4`, `a2b → a2 → a3 → a4`.

## Непроходимые сокращения

- Нельзя растянуть один avatar PNG на обоих персонажей.
- Нельзя класть оружие поверх расслабленной кисти и считать это хватом.
- Нельзя рисовать броню как щит-бейдж поверх старого костюма.
- Нельзя встраивать rarity-рамку в item art: иначе одна картинка не
  переиспользуется в магазине, луте и на персонаже.
- Нельзя включать prototype paths в runtime manifest до отдельного
  `productionReady: true`.
