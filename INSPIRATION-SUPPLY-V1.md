## 0. Задача была не в ранжировании

`InspirationProfileV1.choose()` уже умеет выбрать три карточки на день, зафиксировать их на
дату, скрыть отклонённое и учесть интересы. Механика работает. Не работает **запас**:
каталог — одиннадцать строк.

Поэтому здесь нет ни одной функции «лучше/хуже». Второй ranking поверх одиннадцати строк
ничего бы не изменил. Этот пакет отвечает на два других вопроса: **что имеет право попасть
в каталог** и **что честно сказать, когда подходящего материала нет**.

```
кандидаты источника (много, внешние, непроверенные)
         ↓  admit()          — схема, права, свежесть, доступность, дедуп
допустимый каталог
         ↓  eligibleToday()  — повторы, «не моё», язык, частота источника
конечный пул на день
         ↓  InspirationProfileV1.choose()      ← существует, не трогается
подборка ≤3
         ↓  shortageReport() — если пула не хватило: честный дефицит, не filler
```

### Критерий насыщения — покрытие, а не число роликов

`PRODUCT-CRITICAL-PATH-2026-09.md` §7 прямо предупреждает: критерий — покрытие интересов и
новизна, а не выдуманное «нам нужно ровно N материалов». Поэтому цель по объёму здесь не
ставится, и `admit()` ничего не знает про целевое количество.

Единственное, что можно сказать про объём честно, — это **следствия уже выбранных констант,
а не план закупки**:

- повтор запрещён 45 дней, подборка — 3 в день, значит без повторов 45 дней подряд можно
  прожить только имея 135 разных допустимых материалов;
- минимальное покрытие интереса — 2 материала, профиль допускает до 16 интересов, значит
  один полный профиль без пробелов требует минимум 32. Это нижняя граница, не цель.

Обе цифры — это цена текущих настроек, и её можно снизить, уменьшив `repeatCooldownDays`
или `minPerInterest`. Настоящая приёмка другая и совпадает с §7: несколько существенно
разных профилей получают различимые подборки без нерелевантного filler, а при нехватке
система говорит прямо. Именно это проверяют шесть профилей ниже.

### Сверка с §7 критического пути

| Требование §7 | Где закрыто | Кем |
|---|---|---|
| редакционный / разрешённый supply | схема кандидата + `rights` gate | этот пакет |

| теги | `interestIds` в схеме | этот пакет |

## 1. Схема кандидата

```js
{
  id: 'of-light-study',            // стабильный, уникальный
  source: 'openfilm',              // slug поставщика
  externalId: 'of-0001',           // id внутри источника — основа дедупа
  format: 'video',                 // edit | video | image | quote | podcast
  lang: 'none',                    // ru|en|de|uk|es|ja|none ('none' = без слов)
  contentLocales: ['ru', 'en'],     // только для полностью переведённого text
  durationSec: 464,                // null для image/quote
  interestIds: ['animation', 'creative', 'art'],
  title: { ru: '…', en: '…' },     // ru обязателен
  body:  { ru: '…', en: '…' },     // ru обязателен
  rights: {
    kind: 'cc-by-4.0',             // из закрытого списка
    holder: 'Open Film Collective',// обязателен для всего, что не наше
    url: 'https://…',              // обязателен для всего, что не наше
    embedAllowed: true,
    downloadAllowed: false
  },
  delivery: {
    policy: 'embed',               // local | embed | link | text
    embedUrl: 'https://…',         // для embed, только из allowlist
    sourceUrl: 'https://…',
    assetPath: 'art/…/file.png'    // для local: относительный путь внутри приложения
  },
  imageUrl: 'https://…',           // опционально, свой allowlist
  lastCheckedAt: '2026-09-01T08:00:00.000Z',
  checkMethod: 'playback',         // playback | manual | head
  available: true,                 // true | false | 'unknown'
  availabilityReason: ''           // removed | embed_denied | temporary_error | not_checked
}
```

Отсутствующее поле — это отказ, а не значение по умолчанию. Кандидат без прав, языка или
времени проверки — не «почти годный материал», а неизвестность, которую нельзя показывать.

## 2. Три уровня поставки

Разница между ними правовая, а не техническая. Уровень **выводится** из способа доставки и
прав; заявить его в данных нельзя (тест это проверяет).

| Уровень | Что можно | Что нельзя | Свежесть |
|---|---|---|---|
| `licensed-local` | положить файл к себе (`local`) или воспроизвести текст (`text`) | — | не протухает |
| `official-embed` | показать через официальный проигрыватель источника | **копировать файл** | 30 дней |
| `link-only` | дать ссылку, открытие через attention boundary | встраивать | 30 дней |

**Главное правило пакета: `official` не разрешает копировать файл на сервер.** Официальный
источник даёт право показать, а не право присвоить. Кандидат, объявивший `official-source`
вместе с `downloadAllowed: true`, отвергается как конфликт прав (`rights_conflict`), и
`selfHostAllowed()` для любого `official-embed` возвращает `false` независимо от того, что
написано в данных.

Отсюда же следует, что **массовой выкачки TikTok/YouTube тут нет и появиться не может**:
tier `official-embed` физически не производит плана локального хранения, а `local` требует
относительного пути внутри приложения — абсолютный чужой URL отвергается (`invalid_delivery`).

## 3. Детерминированные правила

### Свежесть

`lastCheckedAt` обязателен, проверка из будущего → `never_checked`.

**Свой материал не протухает вообще.** Уровень `licensed-local` — это файл или текст у нас:
он не исчезает оттого, что прошёл год. Срок годности имеет смысл только для чужого, где
может пропасть источник, а не наш диск. Для чужого — 30 дней, дальше `stale_unverified`.

**Устаревшая проверка не является доказательством удаления.** Она означает ровно «мы не
знаем» и требует перепроверки, а не выбрасывания записи.

### Чем подтверждена живость

`checkMethod` ∈ `playback | manual | head`. Для внешних embed и video/edit/podcast
годится только `playback`; `manual` допускается для статичного материала по ссылке.
`head` даёт `playback_unverified`.

**⚠️ Ломающее изменение контракта пакета (ещё не production):** прежний `manual`
допускал и видео. Теперь просмотр страницы вручную не является playback receipt;
после реального воспроизведения нужно явно записать `playback`. Потребители:
`admit`, `PLAYBACK_PROOFS`, внешние supply manifests. Ни одна существующая строка
каталога не получает новый receipt автоматически.

Причина конкретная: успешный HEAD доказывает, что ответил сервер, и **не** доказывает, что
плеер проигрывает. У YouTube «видео недоступно» и «встраивание запрещено» — разные ошибки,
и обе приходят уже внутри плеера, куда HEAD не заглядывает
([iframe API](https://developers.google.com/youtube/iframe_api_reference)). Поэтому ручная
проверка первого батча обязана включать **воспроизведение внутри Satoru**, а не открытие
страницы.

### Доступность

`available: false` разбирается по `availabilityReason`:

| Причина | Код отказа | Что делать |
|---|---|---|
| `removed`, `embed_denied` | `unavailable` | причина постоянная — запись выбрасывается |
| `temporary_error`, `not_checked` | `availability_unknown` | повторить проверку, запись не терять |

`available: 'unknown'` допустим **только** для `licensed-local`: свой файл либо есть, либо
нет. Для чужого «не знаю» — не основание показывать.

Это и есть требование «удалённое/недоступное медиа не превращается в пустую карточку с
кнопкой смотреть»: такой материал не доходит до каталога вообще.

### Права и доступность — разные проверки

Их нельзя смешивать. Права отвечают «можно ли это показывать», доступность — «работает ли
это сейчас». Материал с безупречными правами может быть удалён; живой материал может не
иметь права на встраивание. В модуле это два независимых гейта с разными кодами отказа.

### Дедуп

Ключ — `source|externalId`, при его отсутствии — `source|нормализованный адрес`. Из двух
одинаковых записей побеждает **более надёжная поставка** (`TIER_RELIABILITY`: local >
embed > link), затем более свежая проверка, затем стабильный id. Проигравший попадает в
`rejected` с кодом `duplicate` — он назван, а не исчезает молча.

`TIER_RELIABILITY` — это надёжность доставки, а не качество материала. Оно используется
только в дедупе.

### Отказы (полный список)

`invalid_schema`, `unknown_format`, `unknown_lang`, `no_interests`, `unknown_rights`,
`missing_attribution`, `missing_rights_url`, `rights_conflict`, `invalid_delivery`,
`embed_host_not_allowed`, `image_host_not_allowed`, `autoplay_in_url`, `insecure_url`,
`duration_out_of_range`, `never_checked`, `stale_unverified`, `unavailable`,
`availability_unknown`, `duplicate`, `missing_text`.

### Частота

Блокировки на день (`eligibleToday`), с названной причиной:

| Код | Правило |
|---|---|
| `repeat_cooldown` | показанное не возвращается 45 дней — **кроме** того, что человек явно попросил показать снова (`requestedIds`) |
| `hidden_by_feedback` | «Не моё» из текущего профиля скрывает материал |
| `language_mismatch` | материал со словами на языке, которого человек не читает; `lang: 'none'` подходит всегда |
| `source_share_exceeded` | один источник не занимает больше 50% пула — **кроме** запрошенного человеком: ограничение разнообразия придумано для автоматической подборки, а не для ответа на «покажи вот это» |

Обратная связь **остаётся в текущем профиле**: модуль принимает `hiddenIds` снаружи и не
имеет ни одной функции записи вкусов (тест запрещает экспорты с именами `record/save/store/persist/feedback`).

### Длительность

`edit` 5–900 с, `video` 5–7200 с, `podcast` 30–10800 с; у `image` и `quote` длительности
нет вообще. Смысл не в аккуратности, а в обещании конечной пачки: материал, который нельзя
закончить, ломает весь раздел.

## 4. Матрица покрытия и отчёт о нехватке

`coverage(items, {interests, formats})` даёт по каждому интересу `total`, разбивку по
форматам и статус `minimal | thin | missing` (порог — 2 материала).

Статус называется `minimal`, а **не** `covered`, намеренно: два материала — это нижняя
граница пригодности, после которой уже можно показывать, а не «интерес закрыт». Слова
«закрыто» в отчёте нет, и тест это проверяет.

`shortageReport(pool, {interests, formats, size})` возвращает:

```js
{
  status: 'ok' | 'thin_formats' | 'shortage' | 'empty',
  requested: 3, available: 2, deliverable: 2, distinctFormats: 1,
  matchingIds: ['sat-next-decision', 'sat-one-question'],
  missingInterests: [...], thinInterests: [...],
  fillerAllowed: false,
  coverage: { … }
}
```

`fillerAllowed` всегда `false`. Это не настройка, а подпись под обещанием: подборка обязана
стать короче, а не добраться до трёх чем попало. Тест проверяет по всем шести профилям, что
ни один материал в `matchingIds` не попал туда без совпадения интереса и формата.

### Шесть синтетических профилей

| Профиль | Интересы / язык | Итог | Почему кейс существует |
|---|---|---|---|
| `p1-movement-ru` | тело, восстановление · ru | `thin_formats` (3 материала, 2 формата) | «есть материал» ≠ «есть разнообразие» |
| `p2-space-science-en` | космос, наука · en · video+podcast | `ok` | единственный профиль с достаточным запасом |
| `p3-creative-visual` | анимация, дизайн · ru+en · edit+video | `ok` (5 материалов) | нормальное покрытие |
| `p4-quiet-reader-ru` | философия, чтение · ru · quote+image | `shortage` (2 из 3) | подборка обязана стать короче |
| `p5-builder-de` | бизнес, продукт · **de** | `empty` + `language_mismatch` | материал есть — но не на его языке |
| `p6-niche-empty` | аниме, супергерои, minecraft | `empty`, без блокировок | материала нет вообще |

### Находка, которую нужно отразить в интерфейсе

`p5` и `p6` дают одинаковый `status: 'empty'`, но это **две разные нехватки**:

- `p5` — материал по теме существует, но человек его не прочитает. Честное сообщение:
  «на немецком по этим темам пока ничего нет».
- `p6` — материала нет ни на одном языке. Честное сообщение: «по этим темам пока ничего нет».

Отличить их можно только по `blocked` из `eligibleToday()` (код `language_mismatch`).
Если UI покажет один и тот же текст, человек в первом случае решит, что его интересы
никому не нужны, хотя проблема в языке. Это решение UI, и оно должно быть принято явно.

Хорошая новость: место для этого уже есть. `public/return-shelf-ui-v1.js` экспортирует
`render`, `renderLoading`, `renderError` и `renderReady` — то есть отдельное состояние
ошибки в рендерере существует, и два вида пустоты не придётся вставлять в карточку
материала. Там же дословно записан контракт, на который опирается весь этот пакет:
«receives an already fixed three-item digest… no fetch, autoplay, scrolling pagination,
reward counters, popularity or randomization».

## 5. API и ошибки

```js
const P = require('./public/inspiration-supply-policy-v1.js'); // или globalThis.InspirationSupplyPolicyV1

P.defaultContext()                         // пороги по умолчанию
P.normalizeCandidate(raw, ctx)             // {ok:true,candidate} | {ok:false,id,code,detail}
P.admit(candidates, ctx)                   // {ok:true,items,rejected,stats} | {ok:false,error}
P.eligibleToday(items, {day, locales, shown, hiddenIds, ctx})  // {ok:true,pool,blocked}
P.coverage(items, {interests, formats, ctx})
P.shortageReport(pool, {interests, formats, size, ctx})
P.toCatalogRows(items, locale)             // шов к InspirationProfileV1
P.fromCatalogV1Row(row, opts)              // {ok, missing[], draft} — миграция существующего каталога
P.selfHostAllowed(candidate)               // можно ли хранить файл у себя
P.classifyTier(candidate) / P.dedupeKey(candidate)
```

Ошибки уровня вызова: `invalid_time` (нет или мусорный `ctx.now`), `invalid_context`
(`candidates` не массив), `invalid_day` (у `eligibleToday`). Все — без side effects.

Контекст (все значения — ручки владельца, не спрятанная политика):

```js
{
  now,                              // обязателен, ISO с зоной
  embedHosts, imageHosts,           // границы; по умолчанию совпадают с app.js
  maxAgeDays: { 'licensed-local': 365, 'official-embed': 30, 'link-only': 30 },
  repeatCooldownDays: 45,
  maxSharePerSource: 0.5,
  minPerInterest: 2,
  locales: ['ru','en','de','uk','es']
}
```

Модуль чистый: ни `Date`, ни `Math.random`, ни сети, ни DOM, ни `State` (проверяется тестом
по исходнику). Календарь считается своей арифметикой, поэтому `2026-02-30` отвергается.

### Граница встраивания сверяется с приложением

`PRODUCTION_EMBED_HOSTS` держит копию allowlist из `inspirationEmbedAllowed()` в `app.js`, и
отдельный тест сравнивает их. Расхождение означало бы, что policy допустит материал, который
приложение молча не покажет: iframe не создастся, карточка останется пустой. Сейчас список —
`www.youtube-nocookie.com`, `www.nps.gov`, `www.dvidshub.net`.

## 6. Сохранение

Модуль **ничего не сохраняет** и не имеет своего хранилища. Он читает кандидатов и контекст
и возвращает результат.

Предлагаемое место для запаса — **манифест в репозитории**, а не новая таблица в аккаунте:

```
data/inspiration-supply/<batch-id>.json   ← кандидаты, проходят admit() в тесте сборки
```

Причины: запас одинаков для всех пользователей, его правки должны проходить ревью, а не
попадать в прод из рантайма; и это единственный вариант, который работает офлайн и не
требует ни одного сетевого запроса на старте.

Что **не** меняется: `settings.inspiration` (профиль, интересы, обратная связь, digest) и
Полка (`shelf`, 40 активных / 160 в истории) остаются там же, где были в v196/v207. Пакет
не заводит второго профиля вкусов и не трогает их контракт.

## 7. Откуда брать материал

Требовалось описать **один реализуемый источник пополнения для первого релиза и один
fallback**, а нужные network/API/rights решения перечислить отдельно.

### Механизм первого релиза: курируемый манифест в репозитории

Батч JSON, проходящий `admit()` в тесте. Ноль сетевых запросов в рантайме, ноль новых
правовых вопросов при показе, работает офлайн, каждая строка прошла ревью. Это реализуемо
сегодня и не требует ни одного решения, кроме содержания батча.

### Кандидаты внешнего батча: NPS + DVIDS, с проверкой каждой работы

Оба хоста внутри существующего fence, но это не доказательство прав на любую работу.
10.09 NPS прямо подтверждает public domain и embed именно Yosemite Stock Footage.
Общие условия DVIDS допускают сторонние права даже без отдельной отметки и требуют
учитывать disclaimer об отсутствии endorsement. Прежнее «правовой вопрос решён v196»
было чрезмерным: сейчас оба источника ещё требуют playback в Satoru, DVIDS — также
проверки конкретной работы и атрибуции. См. источники в integration handoff.

### Fallback: собственный материал Satoru

Цитаты (`text`) и отрисованные кадры (`local`, `tier: licensed-local`). Не зависит ни от
сети, ни от чужих прав, не протухает, уже частично существует (3 цитаты в каталоге).
Закрывает `philosophy`, `focus`, `learning`, `study`, `business`, `product`, `creative`,
`rest`, `recovery` — ровно те интересы, где чужого public-domain материала мало.
Это единственный слой, который гарантированно не может исчезнуть.

### Решения по §7 — приняты интегратором 09.09.2026

Раздел был списком вопросов; ниже — ответы, полученные от Codex, и что из них следует.

1. **Проверка живости — вручную для первого выпуска, но автоматизацию не откладывать.**
   Ручная проверка обязана включать **воспроизведение в Satoru**, а не открытие страницы.
   Дальше — периодическая перепроверка небольшими порциями **до** истечения срока, а не
   после. Чтобы раздел не опустел, нужен запас проверенных материалов, а не молчаливое
   продление срока годности. Кодируется через `checkMethod` и `availabilityReason` (§3).
2. **Автоматического скачивания видео на Railway в первом выпуске нет.** Вопрос
   видеохранилища и бюджета снимается до появления такого механизма. Уровень
   `licensed-local` в первом батче используется только для собственного материала —
   цитат (`text`) и отрисованных кадров (`local`).
3. **Новые embed-хосты добавляются по одному** после технической и правовой проверки.
   Произвольные iframe и адреса, предложенные моделью, не разрешаются. Механически это
   уже так: allowlist инъектируется контекстом и сверяется с `app.js` тестом.
4. **Атрибуция:** короткая строка автора и источника **рядом с материалом**; лицензия,
   ссылка и сведения об изменениях — в доступном раскрытии. Не прятать всё в общие
   настройки ([CC BY 4.0](https://creativecommons.org/licenses/by/4.0/deed.en)).
5. **Два коммерческих трейлера не удаляются автоматически** только потому, что они
   коммерческие. Нужна проверка: официальный ли источник, разрешено ли встраивание,
   соблюдаются ли правила плеера. Не скачивать и не выдавать за собственный контент.
   YouTube допускает определённые коммерческие применения встроенного плеера, но не любые
   ([разъяснение](https://support.google.com/youtube/answer/71011?hl=en)). Проверка этих
   двух карточек ещё нужна.

### Что осталось открытым

- Есть ли у NPS/DVIDS listing/search API и что говорят их условия об автоматическом обходе —
  **не проверено**. До выяснения первый батч собирается вручную.
- Частота и источник периодической перепроверки (откуда идут запросы, что при таймауте) —
  решается при переходе от ручной проверки к автоматической.

## 8. Миграция существующих 11 строк

Все 11 id сохранены. `fromCatalogV1Row()` читает `row.supply` и явные overrides.
Три оригинальные цитаты готовы: `text`, 5 полных `contentLocales`, `available:true`,
