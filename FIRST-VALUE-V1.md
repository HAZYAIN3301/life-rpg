# First Real Value v1 — AG-09 / AG-11 / AG-12 / AG-32

> Невидимый фундамент. `public/first-value-v1.js` — движок состояния, а не UI и не
> экономика. Он записывает, что считается настоящей первой ценностью, и физически
> не умеет засчитать вместо неё яркий экран.

## Какие карточки аудита он закрывает

| Карточка | Статус в аудите | Дыра | Чем закрыта здесь |
|---|---|---|---|
| **AG-09** | FAIL · P0 | Настройка владения (имя, аватар, почта, recovery-код, био, программы, сферы) идёт ДО первого сохранённого действия | Путь существует с `createJourney` и ведёт к результату; конфигурация в него не входит вообще |
| **AG-11** | GAP · P0 | Праздничный переход после неподтверждённой записи | Состояние двигает только событие с полной уликой; отказ возвращает прежний статус и называет причину |
| **AG-12** | FAIL · P0 | Обучение заканчивается тапом по питомцу | `pet_tapped`, `screen_opened`, `xp_received`, `chest_opened` отвергаются в коде, а не по договорённости |
| **AG-32** | GAP · P1 | Обещан маленький вход, таймер запускает другой интервал | `TARGET_MS` живёт в одном месте; превышение ничего не отнимает |

## Границы

Движок **не**:

- не начисляет опыт, золото, серии, предметы — этих слов нет в его состоянии;
- не наказывает за превышение десяти минут — `overTarget` это флаг для тихого
  предложения остановиться или продолжить, и больше ничего;
- не смотрит на часы — `Date.now()` внутри нет, время приходит в событии или в `options`;
- не трогает DOM, сеть и хранилище.

## Состояния

```
new → intent_known → action_ready → action_started → first_value_reached → completed
                                  ↘                ↘                     ↗
                                        deferred  ────────────────────────
```

`deferred` — законный исход, а не провал. Он не отнимает ни улику, ни главное действие;
`resumed` возвращает ровно туда, где человек остановился.

## Маршруты

| Маршрут | Что человек получает | Ожидаемый исход |
|---|---|---|
| `do_now` | Сделать настоящий микрошаг | `quest_completed` |
| `clarify` | Вытащить конкретное следующее действие из реального плана | `next_action_committed`, `real_plan_created` |
| `recover` | Начать настоящую границу восстановления | `recovery_boundary_started` |

Четвёртого маршрута «просто осмотреться» нет намеренно: осмотр не требует пути.

Исход не своего маршрута **не отвергается** — человек, зашедший «уточнить», мог просто
взять и сделать. Несовпадение помечается флагом `routeAligned: false`, чтобы отчёт видел
разницу, а движок не мешал жизни.

## Что считается первой ценностью

Успех требует улики со **всеми четырьмя** полями:

```js
{ entityType, entityId, outcomeType, occurredAt }
```

Разрешённые `outcomeType` (список закрыт):

- `quest_completed` — настоящая задача доведена до конца;
- `next_action_committed` — из плана вынуто конкретное следующее действие и закреплено;
- `recovery_boundary_started` — начата настоящая граница восстановления;
- `real_plan_created` — создан настоящий план, а не заготовка интерфейса.

**Не является первой ценностью** (`NON_VALUE_EVENTS`): `pet_tapped`, `screen_opened`,
`xp_received`, `chest_opened`. Отказ жёсткий: даже полная улика, приложенная к
`pet_tapped`, не проходит. Список существует в коде именно потому, что каждое из этих
событий когда-то уже выдавалось за успех онбординга.

## API

```js
const F = require('./public/first-value-v1.js');   // или globalThis.FirstValueV1
```

### `createJourney({ userId, startedAt, profile }) → state`

Обычный JSON-объект. `profile` — `{ locale, returning, hasPlan, needsRecovery }`, влияет
только на подсказку маршрута.

### `transitionJourney(state, event) → state`

Возвращает **новое** состояние; вход не мутируется. Событие:
`{ id, type, at, ...payload }`.

| Событие | Payload | Из каких состояний |
|---|---|---|
| `route_chosen` | `{ route }` | `new`, `intent_known`, `deferred` |
| `action_ready` | `{ entityType, entityId }` | `intent_known`, `action_ready`, `deferred` |
| `action_started` | `{ entityType, entityId }` | `intent_known`, `action_ready`, `action_started`, `deferred` |
| `outcome_recorded` | улика | `intent_known`, `action_ready`, `action_started`, `first_value_reached`, `deferred` |
| `journey_completed` | — | `first_value_reached`, `completed` |
| `deferred` | `{ reason }` | всё, кроме достигнутых состояний |
| `resumed` | — | `deferred` |

**Идемпотентность.** Повторная доставка того же `event.id` (retry, второе устройство,
перезагрузка на полпути) не двигает путь и не пишет вторую запись в историю:
`lastEvent.reason === 'duplicate_event'`. Без этого «сохранено» после обрыва сети означало
бы разное на клиенте и на сервере — ровно то, чему учит AG-11.

**Отказ — тоже результат.** Состояние возвращается прежним, а `lastEvent.reason` называет
причину (`not_first_value`, `incomplete_reference`, `unknown_route`,
`not_allowed_from_state`, `no_event_id`, …). Молчаливое игнорирование выглядело бы как успех.

**`action_started` принимается прямо из `intent_known`.** «Выбрал и сразу начал» — это один
жест человека; требовать ради него отдельного клика значило бы строить тот же лишний гейт,
из-за которого падает нынешний онбординг.

**Улика принимается почти отовсюду.** Настоящий результат, отвергнутый из-за
непрокликанного промежуточного шага, — это ровно тот гейт, на котором спотыкается
нынешний tutorial. Из `new` улика не принимается: без выбранного маршрута пути ещё нет.

**`firstValueAt` пишется один раз.** Второй настоящий результат принимается и уезжает в
историю (`reason: 'first_value_already_recorded'`), но «первым» уже не станет: на моменте
первого раза держится весь замер AG-09.

**Reload безопасен.** Состояние — обычный JSON. После round-trip путь продолжается
идентично, и дубли по-прежнему узнаются. Состояние со статусом `first_value_reached`, но
без разбираемой улики, откатывается на `action_started`: повреждение once-записи не должно
превращаться в вечный успех.

### `deriveJourneyView(state, options?) → view`

Контракт для UI. Что рисовать — решает Codex; здесь зафиксировано только то, чего рисовать
нельзя.

```js
{
  status, route, suggestedRoute,
  primaryAction,     // ровно один объект или null. НИКОГДА не массив
  otherSupport: [],  // всё остальное
  firstValueReached, firstValueAt, evidence,
  deferred, deferredReason,
  elapsedMs, targetMs, overTarget,
  acceptsEvents,     // какие типы событий примет движок прямо сейчас
  lastEvent,
}
```

`options.now` (ISO) необязателен. Без него `elapsedMs` и `overTarget` равны `null`: часов
внутри нет, иначе вид перестал бы быть воспроизводимым.

**AG-32.** `overTarget: true` не меняет статус, не отнимает улику, не трогает
`primaryAction` и не имеет продолжения в экономике. Тест сравнивает вид «уложился» и вид
«опоздал на 37 минут» поле за полем: различаются только `elapsedMs` и `overTarget`.

### `isMeaningfulOutcome(event) → boolean`

Единственная дверь, через которую что-либо становится первой ценностью. Принимает и
событие, и голую улику, и `{ evidence: {...} }`.

### `getFirstValueEvidence(state) → evidence | null`

Замороженная улика плюс `route`, `routeAligned`, `firstValueAt`. `null`, если ценности нет
или улика повреждена.

## Тесты

`scripts/first-value-v1.test.js` — 28 тестов.

```bash
node --test scripts/first-value-v1.test.js
```

Покрыты: все три маршрута до своего исхода, отказ всем четырём не-ценностям (в том числе с
приложенной уликой), неполная улика по каждому полю, закрытость списка `outcomeType`,
один primary при нескольких кандидатах, идемпотентность при пятикратном retry, JSON
round-trip и продолжение с перечитанного состояния, однократность `firstValueAt`,
повреждённая улика, `deferred`/`resumed`, отсутствие наказания за превышение десяти минут,
отсутствие мутации входа и отсутствие экономики в состоянии и в исходнике.

## Integration contract для Codex

- Модуль в HTML **не подключён** — это зона Codex.
- Хранить состояние как есть (обычный JSON). Никакой отдельной схемы не нужно.
- `event.id` обязан быть стабильным для одного человеческого жеста — иначе
  идемпотентность не работает. Годится `${type}:${entityId}:${occurredAt}`.
- Экономика (XP, золото, серии, сундуки) вызывается **снаружи** по факту
  `view.firstValueReached`, если Альберт решит, что она там нужна. Движок об этом не знает
  и знать не должен.
- `TARGET_MS` — единственный источник десяти минут. Таймер и текст берут его отсюда,
  иначе AG-32 воспроизведётся заново.
