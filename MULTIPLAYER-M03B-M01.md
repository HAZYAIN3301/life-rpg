# M03B + M01 — серверный маршрут и игровой прототип

28.09.2026. База `83e48c94`, shell v310. Продолжение M03A и внешнего
`MULTIPLAYER-ECONOMY-MASTERPLAN-20260928.md`.

## Что можно проверить

- Ядро M03A теперь вызывается через authenticated HTTP API. Сохранённая задача своего
  аккаунта даёт один вклад; повтор не даёт второй. Без отдельного согласия вклад закрыт.
- Выход из компании и её удаление меняют членство и согласие через восстанавливаемый
  журнал. Обезличивание включено в удаление аккаунта. Это реальные серверные операции.
- `/experiments/lighthouse-m01.html` — **отдельный игровой прототип**: две роли на одном
  устройстве, сигнал, согласование маршрута, два разных инструмента, совместная головоломка,
  хроника и выбор желанного предмета. Роли не связаны с аккаунтами. Нет запросов к API.

**Не готовый продукт:** в Племени/Сегодня нет нового входа; приключение ещё не связано
с живыми игровыми выборами и inventory. Прототип не выдаёт золото/XP/предметы и не показывает
их как полученные. Он сохраняет только собственный ключ localStorage
`satoru.lighthouse.m01.v1`; это не серверная квитанция и не межустройственная синхронизация.
Русский текст предназначен для проверки владельцем; пять локализаций обязательны до
включения реального маршрута в приложение. Страница noindex, без новой навигации в shell.

## Контракт HTTP

| Метод и путь | Тело / результат |
|---|---|
| GET `/api/party/adventure` | `{chapter}`; null без согласия; 404 без компании |
| POST `/api/party/adventure/join` | только `{shareProgress:true}` → `{replay,chapter}` |
| POST `/api/party/adventure/contribute` | только `{taskId,revision}` → `{replay,chapter}` |
| POST `/api/party/adventure/withdraw` | только `{}` → `{replay,chapter:null}` |

Идентичность — подписанная сессия + актуальный реестр аккаунтов. Компания — текущее
членство, время — сервер. Тела до 1 KiB, JSON, точные поля; чужой Origin / cross-site
отклоняются. В тело нельзя передать actor/partyId/начисление/задачу/дату.
`readTask` использует существующий `recoverCommitmentJournal` перед своим `tasks.json`.
Операция read → policy → durable write синхронна, без await между ними.

Ошибки: 401 нет сессии; 404 нет компании; 412 нет согласия; 400 неверные поля;
409 конфликт версии, непригодная задача, лимит дня, уже открытый выбор, повтор в другой
компании или предел прототипа; 413 размер; 415 не JSON; 503 хранилище недоступно.
После 503 результат может быть сохранён: читать состояние / повторять **тот же taskId**.
После 409 chapter_conflict — обновить состояние, а не автоматически засчитывать другой шаг.

Глава показывает только агрегат и собственные счётчики. Нет чужих названий, taskId,
хешей и времён. Недельное согласие на XP и согласие на главу независимы:
`/api/social/consent {party:false}` скрывает XP, но не отзывает отдельно выбранную главу.
Для главы есть собственный withdraw; уход из компании отзывает оба доступа по членству.

## Выход, распад и удаление

`party-adventure-lifecycle-v1.json` в корне DATA_DIR — приватное намерение записать
новые `parties.json` и `party-adventures-v1.json` вместе. Не файл `/api/data` аккаунта.
Сначала durable intent, затем согласие, затем членство, затем durable удаление intent.
Перед любым чтением компаний и главы незавершённая операция докатывается. До восстановления
нет частичного успешного ответа. Повреждённый журнал не превращается в пустое состояние.
Поддержан прежний один Node writer; несколько процессов требуют транзакционной БД.

Выход участника сохраняет чужой и общий прогресс, но его active становится false.
Возвращение в компанию не возвращает согласие на главу. Повторное явное вступление не
обнуляет использованные taskId или дневной лимит. При удалении компании все её участники
становятся неактивными. Глава остаётся приватным архивом без пользовательского доступа;
её нельзя запросить по произвольному ID. Это не обещание готовой пользовательской хроники.

Удаление аккаунта добавляет ledger в существующий набор откатываемых файлов, удаляет
аккаунт из реестра и обезличивает вклад, сохраняя общий счётчик. Восстановление файлов теперь
использует 0600 + fsync. Если процесс завершился после удаления строки аккаунта, startup /
часовой privacy sweep / следующее чтение удаляют его ссылки из журнала. Отсутствующий или
повреждённый users.json не считается доказательством отсутствия всех аккаунтов.

Граница: это не полная новая WAL-транзакция удаления всех файлов аккаунта. Старый lifecycle
по-прежнему имеет отдельные стадии переноса каталога, изменения реестра и cleanup; общей
гарантии crash-atomic удаления всего аккаунта этот пакет не заявляет. Проверены обычный
отказ с откатом и конкретный crash после записи реестра для нового журнала приключений.

## Что показывает M01

Две роли на одном телефоне позволяют владельцу пройти всю пробную арку без партнёра.
Согласование маршрута требует одинаковых голосов; разные голоса не теряют прогресс.
В рюкзаке два различных инструмента из трёх; все шесть сочетаний «маршрут × пара» проходимы.
У каждого роль/подсказка/ход. Ошибка сбрасывает только текущие два хода и увеличивает счётчик
попыток. После перезагрузки можно продолжить. Отказ localStorage честно показывается.
Морской путь и сад используют разные подсказки, сочетания ходов и последствия в хронике.

Это wireframe механики, не утверждённый арт мира/аватара. Вводные два условных дела
**не меняют** серверное правило M03A «четыре вклада, UTC»: прототип проверяет быстрый первый
контакт из мастер-плана. После проверки нужен согласованный новый versioned-контракт
этапов и темпа; молча менять правила существующих глав нельзя.

## Следующий gate — участие владельца, а не ещё одна техническая заглушка

Пройти M01 с телефона (желательно затем с одним знакомым) и ответить:
1. Есть ли смысл звать друга ради совместных решений? Где решение оказалось пустым?
2. Оставляем спокойную кооперативную головоломку — рекомендация для первого пилота;
   усиливаем до пошагового босса с несколькими фазами; либо проверяем уютную совместную
   работу без RPG, если сама игра не цепляет.
3. Какой из трёх будущих предметов действительно хочется поставить в Логове и почему?

Источник gate — внешний мастер-план, §25: «После M01: оставить кооперативную приключенческую
RPG … либо сфокусироваться на уютной совместной работе, если игровые решения не находят
отклика. Основание — наблюдаемый прототип». §10.2 требует выбрать один финал после прототипа.
Это необходимость наблюдения/решения о продукте, не техническое требование дополнительного
разрешения на уже порученную разработку.

После ответа: версия правил сцен → первый быстрый шаг → server-owned голоса/инструменты/
исход → персональная квитанция памятного предмета через inventory → вход в Племени/Сегодня
→ две независимые браузерные сессии и 5 языков → 10 пар. Мастерская за золото идёт после
проверки желанного результата; цены, продажи, Pro, аватар и монетизация здесь не менялись.
