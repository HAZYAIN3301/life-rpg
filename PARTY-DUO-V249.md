# Пати: первый полезный совместный шаг — v249

Статус: локальная реализация 08–09.09.2026. Publication gate открыт отдельно;
не считать эту версию опубликованной по наличию файлов или зелёных тестов.

## Разрешённая работа

08.09.2026 владелец разрешил начать направление MULTIPLAYER-RESEARCH-2026-09.md.
Первый целостный этап: знакомое дуо внутри существующей пати → выбранные личные
задачи → приглашение с точным раскрытием → принятие → готовность обоих → общий
конечный интервал → отдельные сохранённые исходы. Публичный подбор, камера, чат,
генерация приключений, новая валюта и новый аватар не входят в этот этап.

## Контракт

- Сессия принадлежит двум участникам, не всей пати. Остальные участники не видят
  её подписи/результаты/личные taskId. taskId возвращается только владельцу задачи.
- Личные задачи не копируются и не принимаются за другого. Сервер проверяет taskId
  только в файлах текущего авторизованного пользователя. Подпись и показ исхода
  разрешаются отдельно от существующего согласия на недельный XP.
- Приглашение не означает начало. Оба явно готовы; готовность действует пять минут.
  Общие начало и конец определяются сервером. Таймер не выставляет галочку.
- «Готово» проходит существующий completeTask/Store/CAS путь, затем сервер проверяет
  факт записи. Частично/остановился не закрывают задачу и не начисляют наград.
- Нет требования закончить одновременно, штрафа, общего проигрыша или продления.
  Переходы идемпотентны; optimistic success запрещён. Отмена отзывает подпись.
- Можно выключить приглашения. Один незавершённый договор на человека, до трёх
  новых приглашений в сутки внутри пати. Pending/review не живут бесконечно;
  история видима до 30 дней. Физическое удаление на записи/старте сервера и часовом
  sweep (при работающем сервере максимум +1 час). Выход/удаление аккаунта удаляет связанные сессии.
- UI: существующие Племя и Today, один уместный вход; сам таймер обновляется без
  перерисовки формы. Только реальные readiness/outcome, не выдуманный online.
- Обычный звук подтверждения и конечная реакция после receipt; reduced motion
  не меняет возможность закончить действие. Нынешние Russo One/темы/арт сохраняются.

## Точная реализация

- `public/party-session-v1.js`: чистые переходы, view, schema/retention; CommonJS/browser.
- `public/party-session-ui-v1.js`: формы/переходы, retry, локализованный UI (RU/EN/DE;
  для UK/ES честный EN fallback), без собственного расчёта допустимых переходов.
- `public/party-session-v1.css`: нынешние темы/шрифт, адаптивность, без нового стилевого слоя.
- `server.js`: server-owned sessions внутри `parties.json`; durable tempfile/fsync/rename.
  Повреждённый реестр не превращается в пустой, чужие идентификаторы не принимаются.
- `GET /api/party/sessions`: лёгкое чтение, не пересчитывает XP и не пишет global registry.
  `POST /api/party/sessions`: создать; `POST /api/party/sessions/:id`: переход;
  `POST /api/party/session-preferences`: только собственное разрешение приглашений.
- `GET /api/party` также возвращает только доступные текущему человеку session views.
- Poll раз в 12 секунд только в видимых Today/Party; таймер обновляет текст без формы.
  Таймаут/сбой дают устаревшее/неизвестное состояние, не мнимый online.
- После потерянного ответа форма фиксирует отправленный payload: повторяется тот же
  gesture, нельзя незаметно подменить согласованную подпись во время retry.
- Сессия ограничена 5–120 минутами, optional назначение до 7 дней. Готовность 5 минут.
  Незавершённая сессия истекает через сутки от намеченного начала/создания, без штрафа.
- Outcome `done` проверяет сохранённый свой task и timestamp после начала. Это подтверждение
  записи self-report, а не независимое доказательство реального выполнения/внимания.

## Открытый фундамент рейда — не реализован в этом срезе

Первоначальный рабочий набросок включал сразу переделку наград. После проверки
call sites эта работа выделена в отдельный P0: нельзя незаметно менять экономику
и legacy-массивы заодно с новой сессией. **Ни fixed raid target, ни новый reward ledger
в v249 не реализованы.** Текущий `members×600` и legacy claim остаются; их риски не закрыты.
Новая дуо-сессия ничего сама не начисляет, поэтому не зависит от старого claim.

Задание Opus №1 в CLAUDE-OPUS5-NEXT-WORK.md: server-owned receipt/ledger service,
durable выдача, legacy compatibility и недельная защита от leave/join-farming.
Текущий +30% XP toast не имеет найденного потребителя в itemXp — явно открытое решение.
Не выдавать старые строки плана ниже/в исследовании за завершённую миграцию.

## Проверка и выпуск

Новые unit/API: `node --test --test-concurrency=2 scripts/party-session-v1.test.js scripts/party-duo-server-v249.test.js`.
7 тестов с составными сценариями: privacy/foreign IDs, limits/readiness/expiry,
immutability/idempotency, done requires saved task, partial, withdraw/retention,
4 изолированных аккаунта, физический write failure, restart, corrupt registry, leave,
read-only poll. Полный runtime suite содержит 1942 теста; итог — в release receipt/DEVLOG.

`node scripts/qa-party-duo.mjs`: настоящий UI двух отдельных Chrome-контекстов,
реальные локальные API/CAS; потеря ответа после durable create → безопасный retry;
готовность → общий таймер → A.done/B.partial → reload. RU/EN/DE, 1440/375px,
dark/light, reduced motion, длинное имя/приватный title, keyboard focus/return.
Скриншоты/receipt: `art-factory/party-duo-v249/`. Пользовательские данные не использованы.
Release shell v249; unchanged CSS/Guide/media сохраняют свои immutable pins.
