# Вдохновение: ежедневные эдиты через Apify · v350

Владелец29.10 поручил автоматическую подборку по выбранным интересам, после
подтверждённого встроенного просмотра v349. Вошёл в Apify Free, самостоятельно
добавил APIFY_API_TOKEN в Railway и ответом «есть» подтвердил предложенный лимит:
до$0.10/run и$4.50/month из бесплатных$5, без карты/подписки.

## Поставка

Сервер использует [TikTok Posts Scraper](https://apify.com/scrapeforge/tiktok-posts)
для поиска по заранее заданным публичным темам. Из сохранённых semantic IDs выбирается
одна тема на запуск, до50 строк, date-posted/this-month. Реальные подпись/теги должны подтверждать
и тему, и формат edit/cinematic/motivation. Автор, длительность1–180с, точный post ID
и URL проверяются; слайды/реклама/очевидно неподходящие метаданные отбрасываются.
Полного анализа видео/звука или доказательства совпадения визуального вкуса тут нет.
Неизвестная тема не превращается в произвольный запрос или нерелевантное заполнение.
Фактическая длительность Scrapeforge в миллисекундах, вопреки опубликованной схеме:
адаптер явно преобразует её в секунды, legacy Clockworks остаётся в своих единицах.
Normalization v2 может перечитать ранее empty dataset по тому же runID без нового POST.

Apify получает публичные общие query. Идентификатор аккаунта, текст вкуса/референсов,
история и feedback туда не отправляются. Нет cookies TikTok, скачивания видео,
обложек/аватаров/музыки, followers/comments/transcripts. API token только на сервере,
Authorization header, никогда URL/HTML/logs. Запросы ограничены по времени и1MiB.

## Расход и восстановление

- До$0.10/run,$0.20/UTC-day,$4.50/UTC-month для всего сервиса; лимит передаётся и Apify.
  Месячный лимит консервативный: резервируется полная сумма, а не обещанная оценка.
  Текущая цена: result$0.30/1000, старт$0.00005/GB (минимум одно событие);
  [актуальная таблица](https://apify.com/scrapeforge/tiktok-posts/pricing).
  Public actor API подтвердил LIMITED_PERMISSIONS и minimum cap$0.05, ниже разрешённых$0.10.
  Free actor допускает один источник/50 строк/один запуск за24 часа. Этот rolling
  предел сохраняется между restart и полночью; прочие интересы используют общий запас.
  У API Dojo Free только5 запусков/месяц: для ежедневной поставки он не используется.
- Durable reservation/starting записывается **до** неидемпотентного POST. Потерянный
  ответ оставляет uncertain и расход зарезервированным; слепого retry в этот день нет.
- Полученный run ID сохраняется. Следующие обращения/restart читают именно его;
  ошибки GET/dataset не создают новый платный запуск. RestartOnError=false.
- Общий serial inventory с durable JSON на существующем volume; текущий Railway
  single replica. Для нескольких процессов нужен общий lock/owner до масштабирования.
- Один запуск на одну тему за24 часа для всего сервиса; неизвестный/повреждённый cache не сбрасывает
  бюджет. Провайдерские IDs и actual usage сохраняются внутри inventory.
- Только метаданные, до600 строк с30-дневным сроком. Подборка может брать новый для
  человека материал из этого запаса: это не обещание публикации каждого ролика сегодня.
  На Free нельзя обещать ежедневный новый поиск по каждому интересу каждого аккаунта:
  очередь тем и масштабирование — отдельный этап, без автоматической покупки тарифа.
- APIFY_WARMUP_TOPICS=anime — согласованная первая ограниченная проверка публичной
  темы. Само наличие ключа не запускает платный probe. Обычное обновление — при открытии
  раздела, выполняется на сервере; Codex/Mac/desktop automation не нужны.
  Startup pilot после первого записанного запуска новой стратегии только читает запас;
  он не отнимает дневной запрос у выбранных интересов после перезапуска сервера.

## Личные рекомендации и владельцы

Новый tagged record personalRecommendation/source=tiktok/rights=linked-public не
выдаёт разрешение на копирование и не допускается общим licensed catalog gate.
Отдельный путь к личной подборке требует HMAC, привязанный к текущему uid и нормализованным
метаданным. Серверный profile owner проверяет подпись до прежнего CAS/WAL; чужой аккаунт
или выдуманные поля её не проходят. Другие settings/tasks/economy не заменяются.

Единственный selector — InspirationProfileV1: ≤3 карточек, feedback/blocked/refs,
фиксированный непустой день и45-дневная история. Pending/ошибка не фиксируют пустой
день как завершённую загрузку. Клиент ограниченно проверяет тот же серверный run,
с abort/account/epoch guard. Прежний совершенно пустой день можно заполнить при
появлении источника; непустой не дополняется и не перемешивается.

Сохранённая рекомендация остаётся своей ссылкой, включая после удаления её метаданных
из rolling inventory. Derived playback model снимает catalog binding только для
этого private record; persisted shelf/CAS не переписывается. Обычный недопущенный
catalogId по-прежнему закрыт. Плеер v349 тот же: explicit Play, isolated exact-ID CSP,
close/end/hidden cleanup, без auto-next/loop/XP. Брендинг и автор TikTok сохраняются.

## Проверки / выпуск

Профильные тесты покрывают реальные HTTP CAS/replay/restart/account isolation,
бюджет/неопределённый POST, дедуп/повторы/refs/feedback, private/shared gate и сохранённый
Play. Локальный UI QA использует явно обозначенную подмену только метаданных провайдера
и настоящий официальный player. Это не доказательство реального ответа Apify.
