# B2.9 — стартовый экран и календарь с данными

Поручение: сначала переделать стартовый экран, затем продолжить подключение.
База: 3118bc84 / B2.8; визуальная основа по-прежнему принятый B2.5.

## Что подключено

- Вход, выбор языка регистрации, регистрация и восстановление получили общую
  композицию с Логовом/героем/Тенью и палитрой B2.5. Сохранены оригинальные DOM
  формы, имена полей, error hosts, обработчики submit, PIN и recovery-код.
  Пароли не копируются в storage, URL или телеметрию. Submit presenter отдельно
  запрещает нативную GET-отправку, даже при сбое инициализации старого обработчика.
- `?welcome=1` показывает вход без logout; сама инициализация и обработчики всегда
  выполняются. После входа — тот же live аккаунт. Это review-вход, не обход auth.
- Принятый календарь: день/неделя/месяц, квесты из Сегодня, создание на выбранную
  дату/время, completion через общий writer, перенос/отмена, намерение недели,
  ориентир времени дня, перенос выбранных прошлых дел, штатный ICS export.
- Реальные сферы/сроки целей/намерения, без demo ID. CalendarChanges принимает
  только расписание. Служебные поля и фактические минуты сохраняются.
- Пакетные перемещения — через commitmentDataCommit, с существующим снятием
  прежней границы и StuckTask.notePostpone. Повтор не прибавляет перенос дважды.
  Undo возвращает дату, время и память откладываний, сохраняет новый actual.
  Снятая временная граница не воскресает; интерфейс сообщает об этом отдельно.
- weeks сохраняет intention/review. Дополнительные поля: dayBudgetsV1 и
  intentionSkillIdsV1; существующие потребители продолжают читать свои поля.
- Локальный proxy сохраняет исходные Host/Origin; protected writes не получают
  403 из-за подмены Host. Startup proxy отражает welcome в URL браузера redirect-ом.

## Доказательства

- TypeScript/esbuild и node --check PASS; **110/110** model/regression/adapter
  tests и **43/43** профильных calendar/auth/commitment-server/overdue/export tests.
- Новые тесты сначала воспроизводили отсутствие live move, потерю метаданных
  undo, выход за полночь, неправильный origin/невидимый query preview; затем GREEN.
- Browser: неверный вход → читаемая ошибка и очищенный пароль; URL не содержит
  поля пароля; регистрация/выбор языка/возврат/восстановление открываются; test-login
  ведёт в аккаунт. Аккаунт не создавался, пароль не менялся, письмо не отправлялось.
- Browser: Сегодня→План, намерение со сферой, ориентир 90 мин, создание встречи
  на 09:05, перенос и undo, смена масштаба, reload. Прямой GET подтвердил точное
  09:05, сохранённые 2 минуты старого квеста и неизменность наград при переносах.
  `review/b29-moved-readback.json`, `b29-undo-readback.json`, `b29-final-readback.json`.
- Проверены 375 и 1280 CSS px; iPhone 14 Simulator показал новый вход в неизменённой
  установленной Debug-оболочке. Скриншоты `review/b29/`: start-375/start-1280,
  plan-375/plan-1280, month-375, ios-start-en. Это не physical-device QA.
- Измеренные пары текста: 8.70:1 (CTA), 10.68:1 (бумага), 6.21:1 (placeholder),
  8.88:1 (вторичный текст на тёмном). Мобильные вкладки высотой 44px; page width
  375 при viewport 375. Полный VoiceOver/text scaling/локализация не заявляются.
- Impeccable detector: одно предупреждение border-accent-on-rounded — underline
  активной вкладки с radius 0, а не рамка карточки; сохранено как нужное состояние.
  Проверка выполнена автором; подагенты запрещены AGENTS.md владельца.

## Границы

Цели/шаги, live Вдохновение/редактор привычек, постоянное расписание и AI-план
пока остаются preview; их примерные данные не записываются в аккаунт. Сроки целей
читаются. Расписание и связи целей — следующий срез, не считать весь План закрытым.
Пакетный перенос проверен coordinator-тестами; весь UI-сценарий пачки и скачивание
ICS через браузер в этом шаге отдельно не прогонялись. Штатный ICS helper покрыт
профильными tests. PIN сохранён структурно, вход с PIN отдельно не проходился.
Новый onboarding после регистрации пока прежний; регистрационный POST и смена
пароля не выполнялись. Ввод в native shell не проверен: CUA вернул noWindowsAvailable
при клике, хотя снимки окна работали. Native проверка ограничена отображением входа.
Внешние ассеты требуют сети; offline/recovery UI и полный runtime suite не пройдены.
Native source, auth/B3/attention, production и 3D/питомцы не менялись.
