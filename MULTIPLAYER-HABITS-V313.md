# v313 — привычки в совместных проектах

Продолжение v312, 29.09.2026. В списке личных вкладов теперь доступны отметки привычек.
Учитывается сохранённый habitlog после восстановления журнала аккаунта, а не состояние DOM.
Подходит полная и двухминутная версия. Время отметки должно быть после начала проекта
и не в будущем. Удалённая до внесения отметка не подходит; исторические отметки не подходят.

Идентичность вклада: аккаунт + группа + тип источника + день привычки + ID привычки.
Отмена/повторная отметка в этот же день, повтор HTTP и переход между двумя проектами
не дают второго вклада. Следующий день — другая отметка. Уже подтверждённый вклад остаётся
при последующей отмене привычки, как ранее вклад дела. Названия видит только владелец.
Сервер не меняет habitlog, задачи, золото или опыт. Совместное завершение по-прежнему
требует двух участников. Контракт tasks v312 и его хеши сохранены без миграции.

`sourceType` в POST `/api/party/projects` необязателен: старый запрос означает `task`.
Новый клиент передаёт `task`/`habit`; неизвестный тип отклоняется. Для привычки `taskId`
содержит JSON-пару [день, ID]. Сервер выбирает источник только из файлов текущего аккаунта;
в общем состоянии остаётся лишь хеш. GET возвращает собственный список с полем `kind`.
Нечитаемые исходные файлы дают 503, а не ложный успех или пустой результат.

## Проверки

- HTTP: чужой источник, историческая/будущая отметка, отказ записи, повтор после отмены,
  повторная отметка, приватность, повреждённый файл; прежние CAS/restart/lifecycle проверки.
- Chrome/WebKit: на движок 12 настоящих завершений задач + 2 отметки привычек через
  transactHabitCompletion; оба проекта, два аккаунта, потеря ответа/повтор, reload,
  отсутствие дополнительного золота. Fixtures задают только исходные задачи/привычки/XP.
- 120 UI-состояний, 5 языков, 2 темы, mobile/desktop; keyboard, 200% текст, reduced motion,
  контраст минимум 6.40:1, page errors 0. Отчёт текущего запуска — work/m06/qa.log,
  снимки и матрица — work/m05/evidence (рабочий каталог существующего QA runner).
- Полный suite: 3241/3241, 0 fail/skip, 56.95 с. Node syntax и diff PASS.
  Production receipt фиксируется во внешнем CHECKPOINT после выпуска.

## Следующая база для фокуса

Аудит: public/app.js bankTimerProgress меняет только накопленное task.actualMin и вызывает
Store.save; stopFocus очищает таймер. Отдельного сохранённого завершения сессии нет.
actualMin не использовать как новый вклад: нельзя отличить старое время, повтор и
завершение того же дела. Нужен отдельный атомарно сохраняемый результат сессии со стабильным
ID, временем, связью с задачей и повтором после отказа. Это отдельная незавершённая часть;
таймер, Senku, оплата и экономика этим выпуском не менялись.
